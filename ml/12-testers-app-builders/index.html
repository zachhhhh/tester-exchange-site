Tester Exchange Tester Exchange തുറക്കുക

App Inventor, Kodular, Flutter, Unity തുടങ്ങിയ builders ഉപയോഗിച്ച് ഉണ്ടാക്കിയ ആപ്പുകൾക്ക് Google Play 12 testers

2026 ഒക്ടോബറിൽ അപ്ഡേറ്റ് ചെയ്തത്

ആപ്പ് ഉണ്ടാക്കാൻ ഏത് tool ഉപയോഗിച്ചു എന്നത് പ്രശ്നമല്ല. നിങ്ങളുടെ Google Play developer അക്കൗണ്ട് പുതിയ personal അക്കൗണ്ടാണെങ്കിൽ, production-ൽ പബ്ലിഷ് ചെയ്യുന്നതിന് മുമ്പ് കുറഞ്ഞത് 12 testers-നൊപ്പം 14 ദിവസത്തെ closed test വേണം. builder, game-engine ഉപയോക്താക്കൾ കുടുങ്ങുന്ന ഭാഗങ്ങളും testers-നെ കണ്ടെത്താനുള്ള ഒരു സൗജന്യ വഴിയും ഈ ഗൈഡ് വിശദീകരിക്കുന്നു.

യഥാർത്ഥ ആളുകൾ 14 ദിവസം സ്വന്തം ഫോണുകളിൽ നിങ്ങളുടെ ആപ്പ് തുറക്കുന്നു. ഒരിക്കൽ പണമടയ്ക്കൂ, അല്ലെങ്കിൽ മറ്റ് ആപ്പുകൾ ടെസ്റ്റ് ചെയ്ത് സൗജന്യമായി നേടൂ.12 testers-നെ നേടൂ

  • ഘട്ടം 2: closed test സെറ്റപ്പ് ചെയ്യുക

  • ഘട്ടം 4: testers-നെ സജീവമാക്കി നിർത്തുക, ഒരു അപ്ഡേറ്റ് അയയ്ക്കുക

എല്ലാ tool-നും ഒരേ നിയമം

Google പരിശോധിക്കുന്നത് നിങ്ങളുടെ developer അക്കൗണ്ടാണ്, tool അല്ല. MIT App Inventor, Kodular, Niotron, Sketchware, Thunkable, FlutterFlow, Flutter, React Native, Expo, Unity, Godot എന്നിവയിൽ ഉണ്ടാക്കിയ എല്ലാ ആപ്പുകളും ഒരേ closed test-ലൂടെ കടന്നുപോകുന്നു.

2023 നവംബർ 13-ന് ശേഷം personal developer അക്കൗണ്ട് ഉണ്ടാക്കിയെങ്കിൽ, production access-ന് അപേക്ഷിക്കുന്നതിന് മുമ്പ് കുറഞ്ഞത് 12 testers തുടർച്ചയായി 14 ദിവസം opt-in ആയിരിക്കണം. Organization അക്കൗണ്ടുകൾക്ക് ഈ നിബന്ധനയില്ല.

ഘട്ടം 1: നിങ്ങളുടെ builder-ന് sign ചെയ്യാവുന്ന release build export ചെയ്യുക

  1. ഒരു Android App Bundle (.aab) export ചെയ്യുക. പുതിയ ആപ്പുകൾക്ക് Google Play-ക്ക് .aab വേണം. മിക്ക builders-ഉം engines-ഉം അത് export ചെയ്യും; നിങ്ങളുടേത് APK മാത്രമേ നൽകുന്നുള്ളൂവെങ്കിൽ, App Bundle ഓപ്ഷനായി അതിന്റെ docs നോക്കുക.
  2. നിങ്ങളുടെ signing key സുരക്ഷിതമായി സൂക്ഷിക്കുക. App Inventor, Kodular പോലുള്ള builders നിങ്ങൾക്കായി keystore ഉണ്ടാക്കുന്നു. അതിന്റെ ബാക്കപ്പ് ഡൗൺലോഡ് ചെയ്യുക. ഓരോ അപ്ഡേറ്റിനും അതേ key വേണം.
  3. Package name ശ്രദ്ധയോടെ തിരഞ്ഞെടുക്കുക. ആപ്പ് Google Play-ൽ എത്തിയാൽ അത് ഒരിക്കലും മാറ്റാനാവില്ല.
  4. Target API level പാലിക്കുക. അടുത്തകാലത്തെ Android പതിപ്പ് target ചെയ്യുന്ന builds മാത്രമേ Google Play സ്വീകരിക്കൂ. Target API level കാരണം അപ്‌ലോഡ് റിജക്റ്റ് ആയാൽ, builder അല്ലെങ്കിൽ engine അപ്ഡേറ്റ് ചെയ്ത് വീണ്ടും export ചെയ്യുക.

ഘട്ടം 2: closed test സെറ്റപ്പ് ചെയ്യുക

  1. Play Console-ൽ Test and release → Testing → Closed testing തുറന്ന് ഒരു track ഉണ്ടാക്കുക.
  2. ഇമെയിൽ ലിസ്റ്റിനു പകരം Google Group വഴി testers-നെ ചേർക്കുക: testers സ്വയം group-ൽ ചേരുന്നു, നിങ്ങൾക്ക് ഇനി ഇമെയിലുകൾ പേസ്റ്റ് ചെയ്യേണ്ടിവരില്ല.
  3. നിങ്ങളുടെ .aab closed track-ൽ അപ്‌ലോഡ് ചെയ്ത്, release notes ചേർത്ത്, റിവ്യൂവിന് അയയ്ക്കുക.
  4. opt-in ലിങ്ക് കോപ്പി ചെയ്യുക. Testers group-ൽ ചേർന്ന്, opt-in ലിങ്ക് തുറന്ന്, "Become a tester" ടാപ്പ് ചെയ്ത്, Google Play-ൽ നിന്ന് ഇൻസ്റ്റാൾ ചെയ്യുന്നു.

ഘട്ടം 3: 14 ദിവസം തുടരുന്ന 12 testers-നെ കണ്ടെത്തുക

ലിസ്റ്റിൽ പന്ത്രണ്ട് പേരുകൾ മതിയാവില്ല. Testers ശരിക്കും ആപ്പ് ഉപയോഗിച്ചോ എന്ന് Google പരിശോധിക്കുന്നു, കുറഞ്ഞത് 12 testers opt-in ആയിരിക്കുമ്പോൾ മാത്രമേ 14 ദിവസം എണ്ണൂ. ഒന്നോ രണ്ടോ പേർ പോയാലും ക്ലോക്ക് നിൽക്കാതിരിക്കാൻ 14-ഓ 15-ഓ പേരെ ചേർക്കുക.

  • Android ഫോണുള്ള സുഹൃത്തുക്കളും കുടുംബവും: സൗജന്യം, പക്ഷേ കുറച്ചു ദിവസം കഴിഞ്ഞാൽ അവർ പലപ്പോഴും ആപ്പ് തുറക്കുന്നത് നിർത്തും.
  • Builder കമ്മ്യൂണിറ്റികളും ഫോറങ്ങളും: സഹ builders-ന് നിയമം മനസ്സിലാകും, പലരും test swap ചെയ്യുന്നു.
  • ഒരു test എക്സ്ചേഞ്ച്: Tester Exchange-ൽ നിങ്ങളുടെ ഫോണിന് മറ്റ് developers-ന്റെ ആപ്പുകൾ ടെസ്റ്റ് ചെയ്യാൻ ലഭിക്കും, ദിവസം ഒരു മിനിറ്റ്, നിങ്ങൾ ടെസ്റ്റ് ചെയ്യുന്ന ഓരോന്നും നിങ്ങളുടെ ആപ്പിന് ഒരു tester-നെ കൊണ്ടുവരും.

ഘട്ടം 4: testers-നെ സജീവമാക്കി നിർത്തുക, ഒരു അപ്ഡേറ്റ് അയയ്ക്കുക

  • Testers-ന് ദിവസവും ഒരു ചെറിയ ജോലി നൽകുക, ആപ്പ് തുറക്കാൻ ഒരു കാരണം ഉണ്ടാകട്ടെ.
  • ദിവസം 7-നോടടുത്ത് പരിഹാരങ്ങളുള്ള പുതിയ build അപ്‌ലോഡ് ചെയ്ത് എന്ത് മാറിയെന്ന് പറയുക. Builders ഇത് വേഗത്തിലാക്കുന്നു: export ചെയ്യുക, അതേ closed track-ൽ അപ്‌ലോഡ് ചെയ്യുക, കഴിഞ്ഞു.
  • എഴുതിയ feedback ചോദിച്ച്, കഴിയുന്നത് പരിഹരിക്കുക. production ചോദ്യങ്ങൾക്ക് യഥാർത്ഥ ഉത്തരങ്ങളും ഇതിലൂടെ ലഭിക്കും.

ഘട്ടം 5: production-ന് അപേക്ഷിക്കുക

14 ദിവസത്തിനു ശേഷം Play Console dashboard-ൽ production access-ന് അപേക്ഷിക്കുക. നിങ്ങൾ testers-നെ എങ്ങനെ കണ്ടെത്തി, അവർ ആപ്പ് എങ്ങനെ ഉപയോഗിച്ചു, അവരുടെ feedback അനുസരിച്ച് എന്ത് മാറ്റി എന്നിവ Google ചോദിക്കും. നിങ്ങളുടെ ടെസ്റ്റിലെ യഥാർത്ഥ സംഖ്യകളോടെ ഉത്തരം നൽകുക. Google സാധാരണയായി ഏകദേശം ഒരാഴ്ചയ്ക്കുള്ളിൽ മറുപടി നൽകും.

പതിവ് ചോദ്യങ്ങൾ

App Inventor അല്ലെങ്കിൽ Kodular ഉപയോഗിച്ച് ഉണ്ടാക്കിയ ആപ്പുകൾക്കും 12 testers വേണോ?

ഉവ്വ്. ഈ നിബന്ധന നിങ്ങളുടെ developer അക്കൗണ്ടിനെ ആശ്രയിച്ചാണ്, tool-നെയല്ല. ആപ്പ് എന്തുപയോഗിച്ച് ഉണ്ടാക്കിയാലും, പുതിയ personal അക്കൗണ്ടുകൾക്ക് 14 ദിവസം opt-in ആയ 12 testers വേണം.

ഞാൻ അയയ്ക്കുന്ന APK testers-ന് ഇൻസ്റ്റാൾ ചെയ്യാമോ?

ഇല്ല. Google Play-യിലെ closed test-ൽ നിന്നുള്ള ഇൻസ്റ്റാളുകൾ മാത്രമേ കണക്കാക്കൂ. Testers Play Console-ലെ ലിങ്ക് വഴി opt-in ചെയ്ത് Play Store-ൽ നിന്ന് ഇൻസ്റ്റാൾ ചെയ്യണം.

closed test തുടങ്ങാൻ പുതിയ build വേണോ?

Closed track-ൽ കുറഞ്ഞത് ഒരു build അപ്‌ലോഡ് ചെയ്തിരിക്കണം. ടെസ്റ്റിനിടെ testers-ന്റെ feedback അനുസരിച്ചുള്ള പരിഹാരങ്ങളോടെ രണ്ടാമതൊരു build അപ്‌ലോഡ് ചെയ്യുന്നത് നല്ലതാണ്.

12 testers-നെ നേടാൻ സൗജന്യ വഴിയുണ്ടോ?

ഉവ്വ്. Test swaps സൗജന്യമാണ്: നിങ്ങൾ മറ്റ് developers-ന്റെ ആപ്പുകൾ ടെസ്റ്റ് ചെയ്യുന്നു, അവർ നിങ്ങളുടേതും. Tester Exchange ഓരോ tester-ന്റെയും ഫോണിൽ ദൈനംദിന ഉപയോഗം സ്ഥിരീകരിക്കുന്നു, അതിനാൽ ടെസ്റ്റിംഗ് യഥാർത്ഥമാണ്.

യഥാർത്ഥ ആളുകൾ 14 ദിവസം സ്വന്തം ഫോണുകളിൽ നിങ്ങളുടെ ആപ്പ് തുറക്കുന്നു. ഒരിക്കൽ പണമടയ്ക്കൂ, അല്ലെങ്കിൽ മറ്റ് ആപ്പുകൾ ടെസ്റ്റ് ചെയ്ത് സൗജന്യമായി നേടൂ.12 testers-നെ നേടൂ

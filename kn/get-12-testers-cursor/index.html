Tester Exchange Tester Exchange ತೆರೆಯಿರಿ

Cursor ನಿಂದ Android ಆ್ಯಪ್ ಮಾಡಿದ್ದೀರಾ? 14 ದಿನಗಳಿಗೆ ನಿಮ್ಮ 12 ಟೆಸ್ಟರ್‌ಗಳನ್ನು ಪಡೆಯಿರಿ

ನವೆಂಬರ್ 2026 ರಂದು ನವೀಕರಿಸಲಾಗಿದೆ

Cursor ನಿಮ್ಮ Android ಆ್ಯಪ್ ಅನ್ನು ಬರೆಯಬಹುದು ಮತ್ತು ಬಿಲ್ಡ್ ಮಾಡಬಹುದು, ಆದರೆ Google Play ಬಯಸುವ 12 ನಿಜವಾದ ಟೆಸ್ಟರ್‌ಗಳನ್ನು ಒದಗಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. ನಿಮ್ಮ ವೈಯಕ್ತಿಕ ಡೆವಲಪರ್ ಖಾತೆಯನ್ನು 13 ನವೆಂಬರ್ 2023 ರ ನಂತರ ರಚಿಸಿದ್ದರೆ, production ಗೆ ಅರ್ಜಿ ಸಲ್ಲಿಸುವ ಮೊದಲು ಕನಿಷ್ಠ 12 ಟೆಸ್ಟರ್‌ಗಳು 14 ನಿರಂತರ ದಿನಗಳ ಕಾಲ ಆಪ್ಟ್-ಇನ್ ಆಗಿರುವ ಕ್ಲೋಸ್ಡ್ ಟೆಸ್ಟ್ ಅನ್ನು ನೀವು ನಡೆಸಬೇಕು. ಈ ಮಾರ್ಗದರ್ಶಿ ಬಂಡಲ್ ಬಿಲ್ಡ್ ಮಾಡುವುದು, ಕ್ಲೋಸ್ಡ್ ಟೆಸ್ಟಿಂಗ್ ಆರಂಭಿಸುವುದು, ಟೆಸ್ಟರ್‌ಗಳನ್ನು ಪಡೆಯುವುದು (ಮೊದಲು ಉಚಿತ, ನಂತರ ಪಾವತಿ) ಮತ್ತು ಏಜೆಂಟ್ ದಾಖಲೆ ಕೆಲಸವನ್ನು ಮಾಡುವಂತೆ Tester Exchange ಅನ್ನು Cursor ಗೆ ಸಂಪರ್ಕಿಸುವುದನ್ನು ಒಳಗೊಂಡಿದೆ.

ನಿಜವಾದ ಜನರು 14 ದಿನ ತಮ್ಮದೇ ಫೋನ್‌ಗಳಲ್ಲಿ ನಿಮ್ಮ ಆ್ಯಪ್ ತೆರೆಯುತ್ತಾರೆ. ಒಮ್ಮೆ ಪಾವತಿಸಿ, ಅಥವಾ ಇತರ ಆ್ಯಪ್‌ಗಳನ್ನು ಟೆಸ್ಟ್ ಮಾಡಿ ಉಚಿತವಾಗಿ ಪಡೆಯಿರಿ.12 testers ಪಡೆಯಿರಿ

1. ರಿಲೀಸ್ ಬಂಡಲ್ (.aab) ಬಿಲ್ಡ್ ಮಾಡಿ

  1. ನಿಮ್ಮ ಮಾಡ್ಯೂಲ್‌ನ build.gradle.kts ನಲ್ಲಿ ರಿಲೀಸ್ ಸೈನಿಂಗ್ ಕಾನ್ಫಿಗರ್ ಮಾಡಲು Cursor ನ ಏಜೆಂಟ್‌ಗೆ ಹೇಳಿ (release ಬಿಲ್ಡ್ ಟೈಪ್‌ಗೆ ಹೊಂದಿಸಿದ storeFile, storePassword, keyAlias ಮತ್ತು keyPassword ಇರುವ signingConfigs ಬ್ಲಾಕ್). ಪಾಸ್‌ವರ್ಡ್‌ಗಳನ್ನು git ನಿಂದ ಹೊರಗಿಡಿ (Android ನ ಬಿಲ್ಡ್ ದಸ್ತಾವೇಜು: https://developer.android.com/build/building-cmdline).
  2. ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ./gradlew bundleRelease ರನ್ ಮಾಡಿ. Gradle ಬಂಡಲ್ ಅನ್ನು ಬಿಲ್ಡ್ ಮಾಡಿ ಸೈನ್ ಮಾಡುತ್ತದೆ; .aab ಸಾಮಾನ್ಯವಾಗಿ app/build/outputs/bundle/release/ ಅಡಿಯಲ್ಲಿ ಕಾಣಿಸುತ್ತದೆ, ಆದರೆ ನಿಮ್ಮ ಸ್ವಂತ ಬಿಲ್ಡ್ ಔಟ್‌ಪುಟ್ ಪರಿಶೀಲಿಸಿ.
  3. ನಿಮ್ಮಲ್ಲಿ keystore ಇಲ್ಲದಿದ್ದರೆ keytool ನಿಂದ ಒಂದನ್ನು ರಚಿಸಿ ಮತ್ತು ಅದರ ಬ್ಯಾಕಪ್ ಇಡಿ. ನಿಮ್ಮ ಮೊದಲ ರಿಲೀಸ್ ಅಪ್‌ಲೋಡ್ ಮಾಡುವಾಗ Google Play App Signing ಅನ್ನು ನೀಡಲಾಗುತ್ತದೆ.

2. Play Console ನಲ್ಲಿ ಕ್ಲೋಸ್ಡ್ ಟೆಸ್ಟಿಂಗ್ ಆರಂಭಿಸಿ

  1. Test and release > Testing > Closed testing ತೆರೆಯಿರಿ, ನಂತರ Create track (ಅಥವಾ Manage track) ಕ್ಲಿಕ್ ಮಾಡಿ.
  2. Create new release ಕ್ಲಿಕ್ ಮಾಡಿ, .aab ಅಪ್‌ಲೋಡ್ ಮಾಡಿ, ರಿಲೀಸ್ ಹೆಸರು ಮತ್ತು ಟಿಪ್ಪಣಿಗಳನ್ನು ಸೇರಿಸಿ, Save as draft, Next, ನಂತರ Start rollout (ಹಂತಗಳು https://support.google.com/googleplay/android-developer/answer/9859348 ನಿಂದ).
  3. ಮೊದಲು Dashboard ನಲ್ಲಿರುವ ಆ್ಯಪ್ ಸೆಟಪ್ ಕಾರ್ಯಗಳನ್ನು ಪೂರ್ಣಗೊಳಿಸಿ, ಇಲ್ಲದಿದ್ದರೆ ರಿಲೀಸ್ ಬಟನ್ ನಿಷ್ಕ್ರಿಯವಾಗಿಯೇ ಇರುತ್ತದೆ.

3. ನಿಮ್ಮ 12 ಟೆಸ್ಟರ್‌ಗಳನ್ನು ಪಡೆಯಿರಿ: ಮೊದಲು ಉಚಿತ, ನಂತರ ಪಾವತಿ

  • ಉಚಿತ ದಾರಿ: ನಿಮ್ಮ ಫೋನ್‌ನಲ್ಲಿ https://testerexchange.com/earn ತೆರೆಯಿರಿ ಮತ್ತು ನಿಮಗೆ ನೀಡಿದ ಆ್ಯಪ್‌ಗಳನ್ನು ಪರೀಕ್ಷಿಸಿ. ನೀವು ಪರೀಕ್ಷಿಸುವ ಪ್ರತಿ ಆ್ಯಪ್ ನಿಮ್ಮ ಆ್ಯಪ್‌ಗೆ ಒಬ್ಬ ಟೆಸ್ಟರ್ ಅನ್ನು ತರುತ್ತದೆ.
  • ಪಾವತಿ ದಾರಿ: ಒಮ್ಮೆ ಪಾವತಿಸಿ, ಟೆಸ್ಟರ್‌ಗಳು ತಾನಾಗಿ ನಿಯೋಜನೆಯಾಗುತ್ತಾರೆ. ಪ್ರಸ್ತುತ ಬೆಲೆಗಳು https://testerexchange.com/llms.txt ನಲ್ಲಿ ಪಟ್ಟಿಮಾಡಲಾಗಿದೆ.
  • 12 ರ ಬದಲು 15 ಟೆಸ್ಟರ್‌ಗಳನ್ನು ಕೇಳಿ, ಇದರಿಂದ ಒಬ್ಬರು ಹೊರಹೋದರೂ ನೀವು Google ನ ಕನಿಷ್ಠಕ್ಕಿಂತ ಕೆಳಗೆ ಇಳಿಯುವುದಿಲ್ಲ.

4. Tester Exchange ಅನ್ನು Cursor ಗೆ ಸಂಪರ್ಕಿಸಿ (ಐಚ್ಛಿಕ)

ಮೊದಲು https://testerexchange.com/api ನಲ್ಲಿ API ಕೀ ರಚಿಸಿ. ನಂತರ ಇದನ್ನು ನಿಮ್ಮ ಪ್ರಾಜೆಕ್ಟ್‌ನ .cursor/mcp.json ನಲ್ಲಿ ಹಾಕಿ, ಅಥವಾ ಎಲ್ಲೆಡೆ ಬಳಸಲು ~/.cursor/mcp.json ನಲ್ಲಿ ಹಾಕಿ (ಫೈಲ್ ಸ್ಥಳಗಳು Cursor ನ MCP ದಸ್ತಾವೇಜಿನಿಂದ, https://cursor.com/docs/context/mcp). ಕೀ commit ಆಗದಿರಲು ಮೊದಲು ನಿಮ್ಮ shell ಪರಿಸರದಲ್ಲಿ TESTER_EXCHANGE_KEY ಹೊಂದಿಸಿ:

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Cursor url ಮತ್ತು headers ಕ್ಷೇತ್ರಗಳಲ್ಲಿ ${env:NAME} ಅನ್ನು ಪರಿಹರಿಸುತ್ತದೆ. ಸರ್ವರ್ ಲೋಡ್ ಆಗದಿದ್ದರೆ Output ಪ್ಯಾನೆಲ್ ತೆರೆದು MCP Logs ಆಯ್ಕೆಮಾಡಿ. ಸರ್ವರ್ OAuth ಇಲ್ಲದ Streamable HTTP ಮೇಲಿನ ಸಾಮಾನ್ಯ MCP; ಸಾರ್ವಜನಿಕ ಟೂಲ್‌ಗಳು (about, pricing, platform_stats) ಕೀ ಇಲ್ಲದೆ ಕೆಲಸ ಮಾಡುತ್ತವೆ.

5. ಏಜೆಂಟ್‌ಗೆ ಕೇಳಿ

  • “com.example.app ಗಾಗಿ Tester Exchange ಬಳಸಿ 15 ಟೆಸ್ಟರ್‌ಗಳನ್ನು ಪಡೆ ಮತ್ತು Play Console ನಲ್ಲಿ ನಾನು ಏನು ಮಾಡಬೇಕು ಎಂದು ಹೇಳು.”
  • “com.example.app ಗಾಗಿ ನನ್ನ Tester Exchange ಕ್ಯಾಂಪೇನ್ ಪರಿಶೀಲಿಸಿ ನಿನ್ನೆ ಎಷ್ಟು ಟೆಸ್ಟರ್‌ಗಳು ಸಕ್ರಿಯರಾಗಿದ್ದರು ಎಂದು ಹೇಳು.”
  • “ಕ್ಯಾಂಪೇನ್ ವರದಿಯನ್ನು ತೆಗೆದುಕೊಂಡು ನಿಜವಾದ ಸಂಖ್ಯೆಗಳ ಆಧಾರದ ಮೇಲೆ ನನ್ನ production ಪ್ರವೇಶ ಉತ್ತರಗಳ ಕರಡು ಬರೆ.”

ಮುಖ್ಯ ಟೂಲ್ get_testers: ಅದು ಆ್ಯಪ್ ಅನ್ನು ಸೇರಿಸುತ್ತದೆ, ಅದರ ಟೆಸ್ಟ್ ತೆರೆಯುತ್ತದೆ ಮತ್ತು Play Console ನಲ್ಲಿ ಟೆಸ್ಟರ್‌ಗಳ Google Group ಸೇರಿಸುವಂತಹ ಮನುಷ್ಯರು ಮಾತ್ರ ಮಾಡಬಹುದಾದ ಹಂತಗಳನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಏಜೆಂಟ್ ನಿಮ್ಮ ಪರವಾಗಿ ಪಾವತಿಸಲು ಅಥವಾ Apply for production ಕ್ಲಿಕ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ.

MCP ಇಲ್ಲವೇ? HTTP API ಬಳಸಿ

https://testerexchange.com/agents/ ನಲ್ಲಿ ಪಟ್ಟಿಮಾಡಿದ ಸಾರ್ವಜನಿಕ apikey ಹೆಡರ್ ಮತ್ತು {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}} ಬಾಡಿಯೊಂದಿಗೆ https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call ಗೆ POST ಮಾಡಿ. ಸ್ಕೀಮಾ https://testerexchange.com/openapi.json ನಲ್ಲಿದೆ. ಇನ್ನಷ್ಟು ಟೂಲ್‌ಗಳು: https://testerexchange.com/guide/ai-builders/ .

ಪದೇ ಪದೇ ಕೇಳುವ ಪ್ರಶ್ನೆಗಳು

Cursor ನನ್ನ ಪರವಾಗಿ 14 ದಿನಗಳ ಟೆಸ್ಟ್ ಪೂರ್ಣಗೊಳಿಸಬಹುದೇ?

ಇಲ್ಲ. ಆ 14 ದಿನಗಳಿಗೆ ತಮ್ಮದೇ Android ಫೋನ್‌ಗಳಲ್ಲಿ ನಿಮ್ಮ ಆ್ಯಪ್ ಬಳಸುವ ನಿಜವಾದ ಜನರು ಬೇಕು. Cursor ಆ್ಯಪ್ ಬಿಲ್ಡ್ ಮಾಡಬಹುದು ಮತ್ತು ಸೆಟಪ್ ನಡೆಸಬಹುದು.

Tester Exchange Cursor ನ ಅಧಿಕೃತ ಇಂಟಿಗ್ರೇಷನ್ ಆಗಿದೆಯೇ?

ಇಲ್ಲ. ಇದು HTTP ಮೂಲಕ ರಿಮೋಟ್ MCP ಬೆಂಬಲಿಸುವ ಯಾವುದೇ ಕ್ಲೈಂಟ್‌ನೊಂದಿಗೆ ಕೆಲಸ ಮಾಡುವ ಸ್ವತಂತ್ರ ಸೇವೆ, ಮತ್ತು Cursor ಅದನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ.

AAB ಎಲ್ಲಿಗೆ ಹೋಗುತ್ತದೆ?

ಅದನ್ನು Play Console ನಲ್ಲಿರುವ ಕ್ಲೋಸ್ಡ್ ಟೆಸ್ಟಿಂಗ್ ರಿಲೀಸ್‌ಗೆ ಅಪ್‌ಲೋಡ್ ಮಾಡಿ, ನಂತರ ಆ ಟ್ರ್ಯಾಕ್‌ನಲ್ಲಿ ನಿಮ್ಮ ಟೆಸ್ಟರ್‌ಗಳ Google Group ಅಥವಾ ಇಮೇಲ್ ಪಟ್ಟಿಯನ್ನು ಸೇರಿಸಿ.

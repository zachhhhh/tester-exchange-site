Google Play પર ગેમ્સ માટે closed testing: Unity, Unreal અને Godot ગાઇડ

નવેમ્બર 2026 માં અપડેટ

ગેમ્સ પણ બીજી કોઈપણ ઍપની જેમ એ જ closed testing જરૂરિયાતમાંથી પસાર થાય છે: તમારું personal developer એકાઉન્ટ 13 નવેમ્બર 2023 પછી બન્યું હોય, તો production માટે અરજી કરતાં પહેલાં સતત 14 દિવસ opt-in રહેલા ઓછામાં ઓછા 12 testers જોઈએ. પણ ગેમ્સની પોતાની મુશ્કેલીઓ છે: મોટા ડાઉનલોડ, build ચલાવી ન શકતા ડિવાઇસ, અને ગેમ એક વાર ખોલીને ફરી ન આવતા testers. આ ગાઇડ ગેમ developers એ શું સેટ કરવું અને testers ને શું કરવા કહેવું તે સમજાવે છે.

સાચા લોકો 14 દિવસ સુધી પોતાના ફોન પર તમારી ઍપ ખોલે છે. એક વાર ચૂકવો, અથવા બીજી ઍપ્સ ટેસ્ટ કરીને મફત મેળવો.12 testers મેળવો

એ જ નિયમ, ગેમ-વિશિષ્ટ જોખમો સાથે

અહીં Google ગેમ્સ અને ઍપ્સને સરખા ગણે છે. સતત 14 દિવસ opt-in રહેલા ઓછામાં ઓછા 12 testers સાથે closed test ચલાવો, પછી production માટે અરજી કરો. Production ફોર્મ tester engagement, feedback અને તમે શું બદલ્યું એ પૂછે છે, એટલે જે test માં કોઈ tutorial થી આગળ રમ્યું નહીં તેના જવાબો નબળા બને છે.

ગેમ્સને બીજી ઍપ્સ કરતાં વધુ નડતાં જોખમો:

  • ડિવાઇસ સુસંગતતા: testers ને "your device isn't compatible" દેખાય છે અને ઇન્સ્ટોલ થતું નથી.
  • ડાઉનલોડનું કદ: મોબાઇલ ડેટા પર મોટું પહેલું ડાઉનલોડ testers ને અટકાવે છે.
  • Session ની લંબાઈ: બે અઠવાડિયા સુધી રોજ 20 મિનિટનો level કોઈ રમશે નહીં.
  • Content ની ખોટ: એક level વાળા vertical slice માં ત્રીજા દિવસ સુધીમાં કરવા જેવું કંઈ બચતું નથી.

પહેલાં તપાસવાના build સેટિંગ

  • Unity: Android App Bundle (.aab) બનાવો, ARM64 ચાલુ કરીને IL2CPP વાપરો (Google Play ને 64-bit સપોર્ટ જોઈએ), અને જરૂર કરતાં વધુ ફોનને બાકાત ન રાખે એવું minimum API level રાખો. Build મોટી હોય તો એક વિશાળ ડાઉનલોડને બદલે Play Asset Delivery વાપરો.
  • Unreal Engine: arm64 સાથે App Bundle તરીકે Android માટે package કરો, Project Settings માં target અને minimum SDK level તપાસો, અને વૈકલ્પિક content ને asset packs માં મૂકીને પહેલું ડાઉનલોડ નાનું રાખો.
  • Godot: Gradle build ચાલુ કરીને Android export template વાપરો અને AAB તરીકે export કરો. arm64-v8a સામેલ છે તેની ખાતરી કરો, અને ઓછી ક્ષમતાવાળા ફોન પર renderer ચકાસો, કારણ કે કેટલાક ડિવાઇસ Forward+ કે Mobile કરતાં Compatibility renderer સારું ચલાવે છે.
  • બધા engines: નવી ઍપ્સ માટે Google Play જે API level હાલ માગે છે તે target કરો, અને Play App Signing વડે sign કરો.

અપલોડ પછી Play Console માં Device catalog ખોલીને જુઓ કે તમારી build કેટલા ડિવાઇસને સપોર્ટ કરે છે. મોટો હિસ્સો બાકાત હોય તો testers આવે તે પહેલાં સુધારો.

Test સેટ કરો

  1. Closed track બનાવો કે ખોલો: Test and release, પછી Testing, પછી Closed testing.
  2. તમારા testers જ્યાં રહે છે તે દેશો ઉમેરો.
  3. ઇમેઇલ લિસ્ટ કે Google Group થી testers ઉમેરો. Tester Exchange સાથે testerexchange-testers@googlegroups.com ઉમેરો.
  4. .aab અપલોડ કરો, release review માટે મોકલો અને તે Published દેખાય ત્યાં સુધી રાહ જુઓ.
  5. Opt-in લિંક શેર કરો. પહેલી વાર તે ચાલુ થવામાં કેટલાક કલાક લાગી શકે છે.

Testers "app not available" કહે તો તે સુધારવાની ગાઇડ જુઓ. તેમાં ખોટાં એકાઉન્ટ, દેશો અને publish ન થયેલા tracks આવરી લીધાં છે.

Testers ને શું રમવા કહેવું

Testers ને થોડી મિનિટોમાં સમાઈ જાય એવા નાના રોજના લક્ષ્યો આપો. સાચું, વૈવિધ્યસભર રમવું તમારા માટે ઉપયોગી છે, અને પછી production ફોર્મમાં તમે એ જ વર્ણવશો.

  • દિવસ 1 થી 3: tutorial અને પહેલો level પૂરો કરો. ગૂંચવણભર્યું કંઈ હોય તો જણાવો.
  • દિવસ 4 થી 7: રોજ એક ટૂંકું session રમો; settings, અવાજ, controls અને pause અજમાવો.
  • દિવસ 8 થી 11: સુધારા સાથેની નવી build અજમાવો; level ફરી રમીને જુઓ કે સારું લાગે છે કે નહીં.
  • દિવસ 12 થી 14: ઉપલબ્ધ સૌથી અઘરી content રમો અને crashes, lag કે battery ખાલી થવાની ફરિયાદ કરો.

તમારી ગેમમાં daily rewards, ટૂંકી daily challenge કે quick mode હોય તો testers ને તે તરફ દોરો. તે રોજના લયમાં સ્વાભાવિક બેસે છે.

Engagement બતાવો

  • Test દરમિયાન ઓછામાં ઓછું એક, ઉત્તમ તો બે અપડેટ મોકલો. જણાવેલા crash ને સુધારવો એ production ફોર્મ માટે સૌથી સારી વાત છે.
  • સાચા ડિવાઇસ પર crashes અને ANRs શોધવા Play Console માં Android vitals અને pre-launch report વાપરો.
  • સરળ ફોર્મમાં લેખિત feedback એકઠો કરો: ડિવાઇસ મૉડલ, તેમણે શું કર્યું, શું થયું.
  • રોજના સક્રિય testers, sessions, મળેલા bugs અને મોકલેલી builds નો લૉગ રાખો.

Multiplayer અને ઑનલાઇન ગેમ્સ

તમારી ગેમને server જોઈએ તો તે બધા 14 દિવસ ચાલુ રાખો, અને testers એકલા હોય ત્યારે પણ ગેમ રમી શકાય તેની ખાતરી કરો. ક્યારેય ન ભરાતું lobby ખાલી test જેવું લાગે છે. શક્ય હોય તો test ના સમય માટે bots કે solo mode ઉમેરો.

સાઇન ઇન જરૂરી હોય તો testers ને ચાલતો guest mode કે સ્પષ્ટ સૂચનાઓ આપો. સાઇન-ઇન ની દીવાલ પહેલા જ દિવસે testers ને ગુમાવે છે.

પૂરતા ખેલાડીઓ મેળવવા

12 ને બદલે 15 testers માગો, કારણ કે ગેમ્સમાં કેટલાક ખેલાડીઓ ઝડપથી છોડી જાય છે. Tester Exchange પોતાના Android ફોન પર રમતા સાચા લોકોને મોકલે છે અને દરેક tester નો રોજનો ઉપયોગ બતાવે છે: 12 માટે $12.99, 15 માટે $14.99 કે 25 માટે $22.99, એક વાર ચૂકવણી. https://testerexchange.com/earn પર બીજા developers ની ઍપ્સ અને ગેમ્સ ટેસ્ટ કરીને તમે મફતમાં testers પણ કમાઈ શકો.

વારંવાર પૂછાતા પ્રશ્નો

ગેમ્સને પણ closed testing જોઈએ?

હા. 13 નવેમ્બર 2023 પછી બનેલા personal એકાઉન્ટની બધી ઍપ્સને, ગેમ્સ સહિત, આ જરૂરિયાત લાગુ પડે છે.

Closed testing દરમિયાન મારી ગેમ અધૂરી હોઈ શકે?

હા, closed test ચાલુ કામ માટે છે. પણ testers ને બે અઠવાડિયા રમવા જેટલી content જોઈએ, અને test દરમિયાન તમારે તેને સુધારતા રહેવું જોઈએ.

કેટલાક testers મારી ગેમ ઇન્સ્ટોલ કેમ કરી શકતા નથી?

સામાન્ય રીતે ડિવાઇસ સુસંગતતા: ઊંચી minimum Android આવૃત્તિ, 64-bit સપોર્ટનો અભાવ, કે જરૂરી હાર્ડવેર features. Play Console માં Device catalog તપાસો.

Testers એ રોજ કેટલું રમવું જોઈએ?

Google કોઈ સંખ્યા નક્કી કરતું નથી. એક લાંબા session પછી કંઈ નહીં, તેના કરતાં દરરોજ ટૂંકું સાચું session વધુ સારું.

Test માટે Play Asset Delivery વાપરવી જોઈએ?

તમારી ગેમ મોટી હોય તો હા. નાનાં પહેલાં ડાઉનલોડથી વધુ testers ખરેખર ઇન્સ્ટોલ કરીને રમવાનું શરૂ કરે છે.

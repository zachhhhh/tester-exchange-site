Tester Exchange Tester Exchange ખોલો

Play Console માં closed testing track કેવી રીતે સેટ કરવો, પગલું-દર-પગલું

નવેમ્બર 2026 માં અપડેટ

તમારી 14 દિવસની ઘડિયાળ શરૂ થાય તે પહેલાં તમારે એવો closed testing track જોઈએ જે publish થયેલો હોય, જેની સાથે testers જોડાયેલા હોય, અને જે કામ કરતી opt-in લિંક આપે. પછી આવતી મોટા ભાગની સમસ્યાઓ, જેમ કે testers ને "app not available" દેખાવું, અહીં ચૂકી ગયેલા પગલાથી આવે છે. આ ગાઇડ Play Console ના હાલના મેનુ (Test and release, પછી Testing, પછી Closed testing) અને Google ના Help Center ને અનુસરે છે.

સાચા લોકો 14 દિવસ સુધી પોતાના ફોન પર તમારી ઍપ ખોલે છે. એક વાર ચૂકવો, અથવા બીજી ઍપ્સ ટેસ્ટ કરીને મફત મેળવો.12 testers મેળવો
આ પેજ પર
  • શરૂ કરતાં પહેલાં
  • 1. Closed track ખોલો કે બનાવો
  • 2. દેશો અને પ્રદેશો પસંદ કરો
  • 3. Testers ઉમેરો: ઇમેઇલ લિસ્ટ કે Google Group
  • 4. Feedback ચેનલ ઉમેરો
  • 5. Release બનાવો અને review માટે મોકલો
  • 6. Opt-in લિંક શેર કરો
  • 7. તપાસો કે 14 દિવસ ગણાઈ રહ્યા છે
  • વારંવાર પૂછાતા પ્રશ્નો

શરૂ કરતાં પહેલાં

  • ઓળખ ચકાસણી પૂરી થયેલું Play Console developer એકાઉન્ટ.
  • Play Console માં બનાવેલી તમારી ઍપ, જેમાં store listing, content rating, target audience, data safety અને બીજા App content declarations ભરેલા હોય. જરૂરી બાબતો ખૂટતી હોય ત્યારે Play Console તમને release review માટે મોકલવા દેતું નથી.
  • તમે હંમેશાં રાખવા માગતા હો એવા package name સાથેનું sign કરેલું Android App Bundle (.aab). તમે તેને પછી બદલી શકતા નથી.
  • તમારા testers માટેની યોજના: Android ફોન અને Google એકાઉન્ટ વાળા ઓછામાં ઓછા 12, ઉત્તમ તો 15 સાચા લોકો.

1. Closed track ખોલો કે બનાવો

  1. Play Console માં તમારી ઍપ પસંદ કરો.
  2. Test and release, પછી Testing, પછી Closed testing પર જાઓ.
  3. Play Console તમને ડિફૉલ્ટ closed track આપે છે (ઘણી વાર Alpha કહેવાય). તેને વાપરો. તમે વધારાના closed tracks બનાવી શકો, પણ જરૂરિયાત માટે એક પૂરતો છે.
  4. Manage track ક્લિક કરો.

2. દેશો અને પ્રદેશો પસંદ કરો

Countries / regions ટૅબ ખોલો અને તમારા testers જ્યાં રહે છે તે દેશો ઉમેરો. તમે પસંદ ન કરેલા દેશમાંનો tester ઍપ ઇન્સ્ટોલ કરી શકશે નહીં.

Google નોંધે છે કે વિતરણ દેશોના ફેરફારો બધા tracks પર લાગુ પડે છે, અને વધારાના closed tracks પોતાનું અલગ દેશ targeting સપોર્ટ કરતા નથી. તમારા testers દુનિયાભરમાં હોય તો સૌથી સહેલો વિકલ્પ તમે કાયદેસર રીતે મોકલી શકો તે દરેક દેશ ઉમેરવાનો છે.

3. Testers ઉમેરો: ઇમેઇલ લિસ્ટ કે Google Group

Testers ટૅબ ખોલો. તમારી પાસે બે વિકલ્પો છે, અને એક track પર બંને વાપરી શકાય.

  • ઇમેઇલ લિસ્ટ: Create email list ક્લિક કરો, નામ આપો, પછી સરનામાં ટાઇપ કરો કે CSV અપલોડ કરો. Google દરેક લિસ્ટ દીઠ 2,000 users સુધી પરવાનગી આપે છે. CSV અપલોડ કરવાથી તે લિસ્ટમાંનાં હાલનાં સરનામાં બદલાઈ જાય છે. દરેક સરનામું એ Google એકાઉન્ટ હોવું જોઈએ જે tester પોતાના ફોનના Play Store માં વાપરે છે.
  • Google Group: group નું સરનામું નાખો, જેમ કે yourgroup@googlegroups.com. ફક્ત group ના સભ્યો જ તમારા test માં જોડાઈ શકે, અને તેમણે opt-in કરતાં પહેલાં group માં જોડાવું પડે. Group માં કોઈને ઉમેરવું એટલું જ તમારે કરવાનું છે; Play Console ને ફરી અડવાનું નથી.

Tester Exchange વાપરો તો Google Groups હેઠળ testerexchange-testers@googlegroups.com group ઉમેરો અને save કરો. એ એક સરનામું અમે મોકલેલા દરેક tester ને તમારી ઍપ ઇન્સ્ટોલ કરવા દે છે. Google Group વિરુદ્ધ ઇમેઇલ લિસ્ટની ગાઇડ પણ જુઓ.

4. Feedback ચેનલ ઉમેરો

એ જ Testers ટૅબ પર feedback URL કે ઇમેઇલ સરનામું ઉમેરો. Testers જોડાય ત્યારે તે જુએ છે. Production access ફોર્મમાં તમારે tester feedback નો સારાંશ આપવો પડશે, એટલે તેને સરળ બનાવો: ટૂંકું Google Form કે ખાસ ઇમેઇલ સરનામું ચાલે.

5. Release બનાવો અને review માટે મોકલો

  1. Closed track પર Create new release ક્લિક કરો.
  2. તમારી .aab અપલોડ કરો. અલગ કારણ ન હોય તો Play App Signing ને તમારી key સંભાળવા દો.
  3. Release નું નામ અને ટૂંકી release notes ઉમેરો, જેમ કે "First closed test build".
  4. Next ક્લિક કરો, ભૂલો સુધારો, પછી Save કરો.
  5. Publishing overview પર જાઓ અને ફેરફારો review માટે મોકલો. Managed publishing ચાલુ હોય તો મંજૂરી પછી Publish પણ ક્લિક કરવું પડે.

નવા એકાઉન્ટ્સ પરની closed test releases લાઇવ થતાં પહેલાં review થાય છે. સમય કલાકોથી કેટલાક દિવસ સુધી બદલાય છે.

6. Opt-in લિંક શેર કરો

Google કહે છે કે ઍપની સ્થિતિ Published થાય ત્યારે જ opt-in લિંક દેખાય છે. તેને Testers ટૅબ પરથી કૉપિ કરો. તે આના જેવી દેખાય છે: https://play.google.com/apps/testing/your.package.name.

પહેલી વાર publish કરો ત્યારે લિંક કામ કરવા લાગે તેમાં કેટલાક કલાક લાગી શકે છે. Testers Google Play માં શોધીને closed tests શોધી શકતા નથી, એટલે તેમને આ લિંક કે તમારી ઍપની Play Store લિંક જોઈએ.

  1. Tester તમે ઉમેરેલા (અથવા તમારા Google Group માં રહેલા) Google એકાઉન્ટથી સાઇન ઇન થાય છે.
  2. તેઓ opt-in લિંક ખોલીને tester બનવા માટે ટૅપ કરે છે.
  3. તે પેજ પરની લિંક વડે Google Play પરથી તમારી ઍપ ઇન્સ્ટોલ કરે છે.
  4. તેઓ તેને ખોલે છે, અને 14 દિવસ દરમિયાન ખોલતા રહે છે.

7. તપાસો કે 14 દિવસ ગણાઈ રહ્યા છે

તમારો Dashboard closed testing ની જરૂરિયાત અને કેટલા testers opt-in છે તે બતાવે છે. દર બે-ત્રણ દિવસે તપાસો. સંખ્યા 12 થી નીચે જાય તો તરત બદલી શોધો, કારણ કે જરૂરિયાત સતત opt-in રહેલા 12 testers ગણે છે.

Test દરમિયાન એ જ track પર ઓછામાં ઓછી એક નવી build અપલોડ કરો. તે Google ને બતાવે છે કે તમે feedback પર કામ કર્યું, અને track પરના testers ને અપડેટ આપમેળે મળે છે.

વારંવાર પૂછાતા પ્રશ્નો

શું હું તેને બદલે internal testing વાપરી શકું?

ના. જરૂરિયાતને closed test જોઈએ. Google એ પણ કહે છે કે internal test માં opt-in થયેલા લોકો તે છોડે નહીં ત્યાં સુધી closed test માં જોડાઈ શકતા નથી.

ઇમેઇલ લિસ્ટ વાપરવી કે Google Group?

Testers આવતા-જતા હોય ત્યારે Google Group સહેલું છે, કારણ કે તમારે track ક્યારેય સંપાદિત કરવો પડતો નથી. મિત્રોના નિશ્ચિત જૂથ માટે ઇમેઇલ લિસ્ટ ચાલે. તમે બંને વાપરી શકો.

મને opt-in લિંક કેમ દેખાતી નથી?

Closed track પરની release publish થાય ત્યારે જ તે દેખાય છે. બાકી review કે મોકલ્યા વગરના ફેરફારો માટે Publishing overview તપાસો.

શું tester ને Google એકાઉન્ટ જોઈએ?

હા. Google કહે છે કે test માં જોડાવા users ને Google એકાઉન્ટ કે Google Workspace એકાઉન્ટ જોઈએ, અને તે તેમના ફોનના Play Store પરનું એકાઉન્ટ હોવું જોઈએ.

શું હું closed test ઍપને પેઇડ બનાવી શકું?

બનાવી શકો, પણ Google કહે છે કે testers એ closed tests માં પેઇડ ઍપ્સ ખરીદવી પડે. Testers ગુમાવવાથી બચવા test ઍપ મફત રાખો.

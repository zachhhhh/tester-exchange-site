Games ද වෙනත් ඕනෑම ඇප් එකක් මෙන් එකම closed testing අවශ්‍යතාවයට යටත්: ඔබේ පුද්ගලික developer ගිණුම 2023 නොවැම්බර් 13 න් පසු සාදා ඇත්නම්, production සඳහා අයදුම් කිරීමට පෙර අඛණ්ඩව දින 14ක් opt-in වී සිටින testers අවම වශයෙන් 12ක් අවශ්‍යයි. නමුත් games වලට ම ආවේණික උගුල් තිබේ: විශාල බාගැනීම්, build එක ධාවනය කළ නොහැකි උපාංග, සහ game එක එක් වරක් විවෘත කර ආපසු නොඑන testers. Game developers සකසා ගත යුතු දේ සහ testers ට කරන්නට කිව යුතු දේ මෙම මාර්ගෝපදේශයෙන් ආවරණය වේ.

එකම නීතිය, games වලට ආවේණික අවදානම් සමඟ

මෙහිදී Google games සහ apps සමානව සලකයි. දින 14ක් අඛණ්ඩව opt-in වී සිටින testers අවම වශයෙන් 12ක් සහිත closed test එකක් ධාවනය කර, පසුව production සඳහා අයදුම් කරන්න. Production ෆෝරමය testers ගේ engagement, feedback සහ ඔබ වෙනස් කළ දේ ගැන අහන නිසා, කිසිවෙකු tutorial එකෙන් එහාට නොගිය test එකක් දුර්වල පිළිතුරු ඇති කරයි.

වෙනත් ඇප් වලට වඩා games වලට වැඩියෙන් බලපාන අවදානම්:

  • උපාංග ගැළපීම: testers ට "your device isn't compatible" පෙනී install කළ නොහැකි වේ.
  • බාගැනීමේ ප්‍රමාණය: mobile data මත විශාල පළමු බාගැනීමක් testers ව අධෛර්යමත් කරයි.
  • Session කාලය: සති දෙකක් තිස්සේ සෑම දිනකම විනාඩි 20ක level එකක් කිසිවෙකු ක්‍රීඩා නොකරයි.
  • අන්තර්ගත හිඟය: level එකක් පමණක් ඇති vertical slice එකක තුන්වන දිනට කරන්න දෙයක් ඉතිරි නොවේ.

මුලින්ම පරීක්ෂා කළ යුතු build සැකසුම්

  • Unity: Android App Bundle (.aab) එකක් සාදන්න, ARM64 සක්‍රීය කර IL2CPP භාවිත කරන්න (Google Play හට 64-bit සහාය අවශ්‍යයි), සහ ඔබට අවශ්‍ය ප්‍රමාණයට වඩා දුරකථන බැහැර නොකරන අවම API මට්ටමක් සකසන්න. ඔබේ build එක විශාල නම්, එක් විශාල බාගැනීමක් වෙනුවට Play Asset Delivery භාවිත කරන්න.
  • Unreal Engine: arm64 සහිත App Bundle එකක් ලෙස Android සඳහා package කරන්න, Project Settings හි target සහ අවම SDK මට්ටම් පරීක්ෂා කරන්න, සහ විකල්ප අන්තර්ගතය asset packs වලට ගෙන පළමු බාගැනීම කුඩා තබාගන්න.
  • Godot: Gradle build සක්‍රීය කර Android export template එක භාවිත කර AAB ලෙස export කරන්න. arm64-v8a ඇතුළත් බව තහවුරු කර, අඩු මට්ටමේ දුරකථනයක renderer එක ටෙස්ට් කරන්න, මන්ද සමහර උපාංග Forward+ හෝ Mobile වලට වඩා Compatibility renderer එක හොඳින් හසුරුවයි.
  • සියලු engines: නව ඇප් සඳහා Google Play දැනට අවශ්‍ය කරන API මට්ටම ඉලක්ක කර, Play App Signing සමඟ sign කරන්න.

Upload කිරීමෙන් පසු, ඔබේ build එක කොපමණ උපාංග ගණනකට සහාය දක්වනවාදැයි බැලීමට Play Console හි Device catalog විවෘත කරන්න. විශාල කොටසක් බැහැර කර ඇත්නම්, testers පැමිණීමට පෙර එය නිවැරදි කරන්න.

Test එක සකසන්න

  1. Closed track එක විවෘත කරන්න හෝ සාදන්න: Test and release, ඉන්පසු Testing, ඉන්පසු Closed testing.
  2. ඔබේ testers ජීවත් වන රටවල් එක් කරන්න.
  3. Email list එකකින් හෝ Google Group එකකින් testers එක් කරන්න. Tester Exchange සමඟ නම් testerexchange-testers@googlegroups.com එක් කරන්න.
  4. .aab එක upload කර, release එක සමාලෝචනයට යවා, එය Published ලෙස පෙනෙන තුරු රැඳී සිටින්න.
  5. Opt-in link එක බෙදාගන්න. පළමු වතාවට, එය ක්‍රියාත්මක වීමට පැය කිහිපයක් ගත විය හැක.

Testers "app not available" යැයි වාර්තා කරන්නේ නම්, එය විසඳීම පිළිබඳ මාර්ගෝපදේශය බලන්න. එයින් වැරදි ගිණුම්, රටවල් සහ publish නොකළ tracks ආවරණය වේ.

Testers ට ක්‍රීඩා කිරීමට කියන්නේ කුමක්ද

Testers ට විනාඩි දෙකක් තුළ කළ හැකි කුඩා දෛනික ඉලක්ක දෙන්න. ඔබට උපකාරී වන්නේ සැබෑ, විවිධාකාර ක්‍රීඩාවයි, සහ පසුව production ෆෝරමයේ ඔබ විස්තර කරන්නේද එයයි.

  • 1 සිට 3 දක්වා දින: tutorial එක සහ පළමු level එක අවසන් කරන්න. ව්‍යාකූල ඕනෑම දෙයක් වාර්තා කරන්න.
  • 4 සිට 7 දක්වා දින: දිනකට කෙටි session එකක් ක්‍රීඩා කරන්න; settings, ශබ්දය, පාලන සහ pause කිරීම උත්සාහ කරන්න.
  • 8 සිට 11 දක්වා දින: නිවැරදි කිරීම් සහිත නව build එකක් උත්සාහ කරන්න; එය වඩා හොඳ දැයි බැලීමට level එකක් නැවත ක්‍රීඩා කරන්න.
  • 12 සිට 14 දක්වා දින: ඇති අපහසුම අන්තර්ගතය ක්‍රීඩා කර crashes, lag හෝ බැටරි පරිභෝජනය වාර්තා කරන්න.

ඔබේ game එකේ දෛනික ත්‍යාග, කෙටි දෛනික challenge එකක් හෝ ඉක්මන් mode එකක් තිබේ නම්, testers ව ඒ වෙත යොමු කරන්න. එය දෛනික රිද්මයට ස්වභාවිකවම ගැළපේ.

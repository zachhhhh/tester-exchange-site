Ginawa mo ang Android app mo gamit ang Cursor? Kunin ang 12 testers mo sa loob ng 14 na araw

Na-update noong Nobyembre 2026

Kayang isulat at i-build ng Cursor ang Android app mo, pero hindi ito makapagbibigay ng 12 totoong testers na hinihingi ng Google Play. Kung ginawa ang personal developer account mo pagkatapos ng 13 Nobyembre 2023, kailangan mong magpatakbo ng closed test na may kahit 12 testers na naka-opt in nang 14 na tuloy-tuloy na araw bago mag-apply para sa production. Saklaw ng gabay na ito ang pag-build ng bundle, pagsisimula ng closed testing, pagkuha ng testers (libre muna, bayad pangalawa) at pagkonekta ng Tester Exchange sa Cursor para magawa ng agent ang papeles.

1. I-build ang release bundle (.aab)

  1. Ipakiusap sa agent ng Cursor na i-configure ang release signing sa build.gradle.kts ng module mo (isang signingConfigs block na may storeFile, storePassword, keyAlias at keyPassword, itinakda sa release build type). Huwag isama ang mga password sa git (build docs ng Android: https://developer.android.com/build/building-cmdline ).
  2. Patakbuhin ang ./gradlew bundleRelease sa terminal. Bina-build at sina-sign ng Gradle ang bundle; karaniwang lumalabas ang .aab sa app/build/outputs/bundle/release/, pero tingnan ang sarili mong build output.
  3. Gumawa ng keystore gamit ang keytool kung wala ka pa, at i-back up ito. Iniaalok ang Google Play App Signing kapag ina-upload mo ang una mong release.

2. Simulan ang closed testing sa Play Console

  1. Buksan ang Test and release > Testing > Closed testing, tapos Create track (o Manage track).
  2. I-click ang Create new release, i-upload ang .aab, maglagay ng release name at notes, Save as draft, Next, tapos Start rollout (mga hakbang mula sa https://support.google.com/googleplay/android-developer/answer/9859348 ).
  3. Tapusin muna ang app setup tasks sa Dashboard, kung hindi ay mananatiling naka-disable ang release button.

3. Kunin ang 12 testers mo: libre muna, bayad pangalawa

  • Libreng paraan: buksan ang https://testerexchange.com/earn sa phone mo at i-test ang mga app na ibibigay sa iyo. Bawat app na ite-test mo ay nagdadala ng tester sa app mo.
  • Bayad na paraan: magbayad nang isang beses at awtomatikong itatalaga ang testers. Nakalista ang kasalukuyang presyo sa https://testerexchange.com/llms.txt .
  • Humingi ng 15 testers sa halip na 12 para hindi ka mapababa sa minimum ng Google kapag may umalis.

4. Ikonekta ang Tester Exchange sa Cursor (opsyonal)

Gumawa muna ng API key sa https://testerexchange.com/api . Pagkatapos, ilagay ito sa .cursor/mcp.json sa project mo, o sa ~/.cursor/mcp.json para magamit kahit saan (mga lokasyon ng file mula sa MCP docs ng Cursor, https://cursor.com/docs/context/mcp ). Itakda muna ang TESTER_EXCHANGE_KEY sa shell environment mo para hindi ma-commit ang key:

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Nire-resolve ng Cursor ang ${env:NAME} sa mga field ng url at headers. Kung hindi ma-load ang isang server, buksan ang Output panel at piliin ang MCP Logs. Plain MCP over Streamable HTTP na walang OAuth ang server; gumagana nang walang key ang mga pampublikong tool (about, pricing, platform_stats).

5. Tanungin ang agent

  • “Gamitin ang Tester Exchange para kumuha ng 15 testers para sa com.example.app at sabihin sa akin kung ano ang dapat kong gawin sa Play Console.”
  • “Tingnan ang Tester Exchange campaign ko para sa com.example.app at sabihin kung ilang testers ang aktibo kahapon.”
  • “Kunin ang campaign report at i-draft ang mga sagot ko para sa production access mula sa totoong numero.”

Ang pangunahing tool ay get_testers: idinaragdag nito ang app, binubuksan ang test nito at ibinabalik ang mga hakbang na tao lang ang makakagawa, tulad ng pagdaragdag ng Google Group ng testers sa Play Console. Hindi makakapagbayad o makakapag-click ng Apply for production ang agent para sa iyo.

Walang MCP? Gamitin ang HTTP API

Mag-POST sa https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call gamit ang pampublikong apikey header na nakalista sa https://testerexchange.com/agents/ at ang body na {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}} . Nasa https://testerexchange.com/openapi.json ang schema. Iba pang tool: https://testerexchange.com/guide/ai-builders/ .

Mga madalas itanong

Magagawa ba ng Cursor ang 14 na araw na test para sa akin?

Hindi. Kailangan ng 14 na araw ang totoong tao na gumagamit ng app mo sa sarili nilang Android phone. Kayang i-build ng Cursor ang app at patakbuhin ang setup.

Opisyal bang integration ng Cursor ang Tester Exchange?

Hindi. Independent na serbisyo ito na gumagana sa anumang client na sumusuporta sa remote MCP over HTTP, na sinusuportahan ng Cursor.

Saan napupunta ang AAB?

I-upload ito sa isang closed testing release sa Play Console, tapos idagdag ang Google Group o email list ng testers mo sa track na iyon.

May libreng paraan ba para makakuha ng 12 testers?

Oo. I-test ang apps ng ibang developers sa https://testerexchange.com/earn ; bawat app na ite-test mo ay nagdadala ng tester sa app mo.

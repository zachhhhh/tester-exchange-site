Tester Exchange Buksan ang Tester Exchange

I-automate ang closed testing ng Google Play gamit ang AI agents

Na-update noong Nobyembre 2026

Kung nagsa-ship ka na ng code gamit ang AI agent, puwede mo ring ipaubaya sa kanya ang karamihan sa gawaing pang-administrasyon ng closed testing requirement ng Google Play: pag-lista ng app mo, pag-recruit ng testers, pagsubaybay sa progress at paghahanda ng mga numero para sa production access form. May MCP server, isang-endpoint na HTTP API at A2A agent card ang Tester Exchange para dito. Ipinapakita ng gabay na ito kung paano ikonekta ang Claude Code, Claude Desktop, Cursor at iba pang clients, ano ang dapat itanong, at ang mga bahaging walang agent na makakagawa para sa iyo.

Ano ang kaya at hindi kaya ng agent

Inaatasan ng Google ang mga personal developer account na ginawa pagkatapos ng 13 Nobyembre 2023 na magpatakbo ng closed test na may hindi bababa sa 12 testers na naka-opt in sa loob ng 14 na tuloy-tuloy na araw bago mag-apply para sa production. Karamihan ng gawain sa paligid nito ay koordinasyon, na magaling gawin ng mga agent.

  • Kaya ng agent: idagdag ang app mo, magbukas ng tester campaign, gamitin ang credits mo, tingnan kung ilang testers ang aktibo, i-pause o isara ang campaign, kunin ang daily-activity report at tumulong mag-draft ng mga sagot sa production access mula rito.
  • Kailangang gawin ng tao: idagdag sa closed track sa Play Console ang Google Group ng testers, i-publish ang release, magbayad para sa credits (laging sa browser ng tao ang checkout) at i-click ang Apply for production.
  • Walang makakapag-automate: ang 14 na araw ng totoong paggamit. Totoong tao sa sarili nilang Android phones ang gumagawa nito, at iyon mismo ang punto ng patakaran ng Google.

1. Gumawa ng token

  1. Mag-sign in sa https://testerexchange.com/api.
  2. Gumawa ng personal token. Nagsisimula ito sa tx_. Kopyahin ito ngayon at itago na parang password.
  3. Puwedeng i-revoke ang mga token anumang oras. Kaya ng token na gumastos ng credits sa campaigns, pero hindi ito makakabayad, makakapag-withdraw ng pera o makakapagbura ng account mo.

2. Ikonekta ang MCP server

Gumagamit ang MCP server ng Streamable HTTP sa https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp. Ipadala ang token mo sa header na Authorization: Bearer tx_YOUR_TOKEN.

Claude Code: patakbuhin ito nang isang beses sa terminal mo.

claude mcp add --transport http tester-exchange https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp --header "Authorization: Bearer tx_YOUR_TOKEN"

Claude Desktop, Cursor, VS Code at iba pang clients na may JSON config: magdagdag ng server na may pangalang tester-exchange, type na http, ang URL sa itaas, at headers entry na may Authorization na nakatakda sa Bearer tx_YOUR_TOKEN. Nakadepende sa client mo ang eksaktong lokasyon ng config file; tingnan ang MCP documentation nito.

Mga client na URL lang ang tinatanggap (ilang ChatGPT at web connectors): nakalista sa docs sa https://testerexchange.com/agents/ ang URL form para sa kanila. Kahit walang token, gumagana pa rin ang mga public tool (kung ano ang Tester Exchange, presyo, platform stats).

3. Ang isang tool na uunahin: get_testers

Hindi mo kailangang aralin ang buong listahan ng tools. Ang pangunahing tool ay get_testers(package_name, name?). Sa isang tawag, idinadagdag nito ang app mo, binubuksan ang test, ginagamit ang credits mo at ibinabalik ang progress mo kasama ang mga hakbang na tao lang ang makakagawa, tulad ng pagdaragdag ng Google Group sa Play Console. Tawagin ulit ito anumang oras para tingnan ang progress.

Sakop ng ibang tools ang mga detalye: my_apps, campaign_report (testers, daily activity, feedback at production-access data), add_testers, set_campaign_status (pause, resume o close; bumabalik sa balance mo ang hindi nagamit na credits), share_kit at buy_credits_links, na nagbabalik ng checkout links para bayaran ng tao.

Mga prompt na gumagana

  • "Kumuha ng 15 testers para sa com.example.app at sabihin sa akin kung ano ang kailangan kong gawin sa Play Console."
  • "Tingnan ang Tester Exchange campaign ko para sa com.example.app. Ilang testers ang aktibo bawat araw ngayong linggo?"
  • "Kunin ang campaign report at i-draft ang mga sagot ko sa production access. Gamitin lang ang totoong numero."
  • "Isara ang campaign para sa com.example.app dahil na-approve na ang production access."

Humingi ng 15 testers sa halip na 12, para hindi ka maibaba ng isang dropout sa minimum ng Google.

HTTP API para sa scripts at CI

Kung hindi marunong ng MCP ang tool mo, gamitin ang HTTP endpoint: POST https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call. JSON ang body, na may p_token (ang tx_ token mo), p_action (halimbawa help, my_apps o start_campaign) at p_args (halimbawa package_name at bilang ng testers). Ipadala ang public apikey header na nakasaad sa docs.

Tawagin muna ang help action: ibinabalik nito ang lahat ng actions at ang mga argument nila. Nasa https://testerexchange.com/openapi.json ang buong schema, na gumagana sa ChatGPT custom GPT actions at iba pang OpenAPI tools.

A2A agent card

Para sa agent-to-agent setups, naglalathala ang Tester Exchange ng A2A agent card sa https://testerexchange.com/.well-known/agent-card.json. Matutuklasan ng mga orchestrator na sumusuporta sa A2A protocol kung ano ang inaalok ng agent at paano ito tatawagin. Gamitin ang parehong tx_ token para sa anumang konektado sa account mo.

Buong takbo, mula simula hanggang katapusan

  1. Ina-upload mo ang una mong .aab sa closed track sa Play Console.
  2. Tinatawag ng agent mo ang get_testers para sa package name mo at sinasabihan kang idagdag ang testerexchange-testers@googlegroups.com sa ilalim ng Google Groups sa closed track.
  3. Idinadagdag mo ang group, nagse-save, at tinitiyak mong published ang release.
  4. Kung kulang ang credits mo, bibigyan ka ng agent ng checkout link. Magbabayad ka ($12.99 para sa 12 testers, $14.99 para sa 15, $22.99 para sa 25) o kikita ka ng credits nang libre sa pag-test ng ibang apps sa https://testerexchange.com/earn.
  5. Ini-install at ginagamit ng totoong testers ang app mo sa loob ng 14 na araw. Sinusuri ng agent mo ang progress araw-araw at binababalaan ka kapag bumaba ang aktibong testers.
  6. Sa day 15, kinukuha ng agent ang campaign report at dina-draft ang mga sagot mo sa production access. Rerepasuhin mo ang mga ito at i-click ang Apply for production.

Mga paalala sa seguridad

  • Huwag ilagay ang tokens sa git. Ilagay ang mga ito sa secret store ng client mo o sa environment variable.
  • Hash lang ang itinatago naming anyo ng tokens at hanggang 10 kada account ang limitasyon. I-revoke ang anumang token na hindi mo na ginagamit.
  • Basahin ang isinulat ng agent sa production form mo bago ka mag-submit. Hinihingi ng Google na ilarawan mo nang tapat ang test mo.

Mga madalas itanong

Kaya bang tapusin ng AI agent ang 14-day test para sa akin?

Hindi. Kailangan ng 14 na araw ang totoong taong gumagamit ng app mo sa sarili nilang phones. Ang agents ang bahala sa setup, monitoring at reporting.

Puwede bang magbayad ang agent para sa testers?

Hindi. Makapagbabalik ito ng checkout links, pero laging sa browser ng tao nangyayari ang bayad.

Aling mga client ang gumagana sa MCP server?

Anumang client na sumusuporta sa remote MCP sa Streamable HTTP na may custom header, kasama ang Claude Code, Claude Desktop, Cursor at VS Code. Ang iba ay puwedeng gumamit ng HTTP API.

Saan ako kukuha ng token?

Sa https://testerexchange.com/api pagkatapos mag-sign in. Nagsisimula sa tx_ ang tokens at puwedeng i-revoke anumang oras.

May binabago ba ang agent sa Play Console ko?

Wala. Walang access ang agent sa Play Console mo. Sasabihin lang nito ang mga hakbang na gagawin mo roon.

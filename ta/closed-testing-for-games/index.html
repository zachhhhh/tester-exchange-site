Google Play-ல் கேம்களுக்கான closed testing: Unity, Unreal, Godot வழிகாட்டி

நவம்பர் 2026-ல் புதுப்பிக்கப்பட்டது

எந்த ஆப்பையும் போலவே கேம்களுக்கும் அதே closed testing தேவைதான்: உங்கள் personal developer கணக்கு 2023 நவம்பர் 13-க்குப் பிறகு உருவாக்கப்பட்டிருந்தால், production-க்கு விண்ணப்பிக்கும் முன் குறைந்தது 12 tester-கள் தொடர்ச்சியாக 14 நாட்கள் opt-in செய்திருக்க வேண்டும். ஆனால் கேம்களுக்குத் தனிப்பட்ட சிக்கல்கள் உண்டு: பெரிய பதிவிறக்கங்கள், build-ஐ இயக்க முடியாத சாதனங்கள், கேமை ஒருமுறை திறந்துவிட்டு திரும்பவே வராத tester-கள். கேம் developer-கள் என்ன அமைக்க வேண்டும், tester-களிடம் என்ன செய்யச் சொல்ல வேண்டும் என்பதை இந்த வழிகாட்டி விளக்குகிறது.

உண்மையான மனிதர்கள் தங்கள் சொந்த போன்களில் 14 நாட்கள் உங்கள் ஆப்பைத் திறக்கிறார்கள். ஒருமுறை பணம் செலுத்துங்கள், அல்லது மற்ற ஆப்களை டெஸ்ட் செய்து இலவசமாகப் பெறுங்கள்.12 tester-களைப் பெறு

அதே விதி, கேம்களுக்கே உரிய ஆபத்துகளுடன்

இதில் Google கேம்களையும் ஆப்களையும் ஒன்றுபோலவே நடத்துகிறது. குறைந்தது 12 tester-கள் 14 நாட்கள் தொடர்ந்து opt-in-ல் இருக்கும் closed test ஒன்றை நடத்தி, பிறகு production-க்கு விண்ணப்பியுங்கள். Production படிவம் tester ஈடுபாடு, கருத்துகள், நீங்கள் என்ன மாற்றினீர்கள் என்பவற்றைப் பற்றிக் கேட்கும்; tutorial-ஐத் தாண்டி யாரும் விளையாடாத test என்றால் பதில்கள் பலவீனமாக இருக்கும்.

மற்ற ஆப்களை விட கேம்களை அதிகம் பாதிக்கும் ஆபத்துகள்:

  • சாதன இணக்கம்: tester-கள் “your device isn't compatible” எனப் பார்த்து install செய்ய முடியாமல் போகிறார்கள்.
  • பதிவிறக்க அளவு: மொபைல் டேட்டாவில் பெரிய முதல் பதிவிறக்கம் tester-களை விலகச் செய்கிறது.
  • Session நீளம்: இரண்டு வாரங்கள் தினமும் 20 நிமிட level-ஐ யாரும் விளையாட மாட்டார்கள்.
  • Content இடைவெளிகள்: ஒரே level கொண்ட vertical slice மூன்றாம் நாளுக்குள் செய்வதற்கு எதுவும் இல்லாமல் போகும்.

முதலில் சரிபார்க்க வேண்டிய build அமைப்புகள்

  • Unity: Android App Bundle (.aab) உருவாக்குங்கள், ARM64 இயக்கப்பட்ட IL2CPP-ஐப் பயன்படுத்துங்கள் (Google Play 64-bit ஆதரவைக் கோருகிறது), தேவைக்கு அதிகமான போன்களை விலக்காத குறைந்தபட்ச API level-ஐ அமையுங்கள். உங்கள் build பெரியதாக இருந்தால், ஒரே பெரிய பதிவிறக்கத்துக்குப் பதிலாக Play Asset Delivery-ஐப் பயன்படுத்துங்கள்.
  • Unreal Engine: arm64 உடன் App Bundle ஆக Android-க்கு package செய்யுங்கள், Project Settings-ல் target மற்றும் குறைந்தபட்ச SDK level-களைச் சரிபாருங்கள், விருப்பத் தேர்வான content-ஐ asset pack-களுக்கு நகர்த்தி முதல் பதிவிறக்கத்தைச் சிறியதாக வையுங்கள்.
  • Godot: Gradle build இயக்கப்பட்ட Android export template-ஐப் பயன்படுத்தி AAB ஆக export செய்யுங்கள். arm64-v8a சேர்க்கப்பட்டுள்ளதை உறுதிசெய்து, renderer-ஐ குறைந்த திறன் போனில் சோதியுங்கள்; சில சாதனங்கள் Forward+ அல்லது Mobile-ஐ விட Compatibility renderer-ஐ நன்றாகக் கையாளும்.
  • அனைத்து engine-களுக்கும்: புதிய ஆப்களுக்கு Google Play தற்போது கோரும் API level-ஐ target செய்யுங்கள், Play App Signing மூலம் கையொப்பமிடுங்கள்.

பதிவேற்றிய பிறகு, உங்கள் build எத்தனை சாதனங்களை ஆதரிக்கிறது என்பதைப் பார்க்க Play Console-ல் Device catalog-ஐத் திறங்கள். பெரிய பங்கு விலக்கப்பட்டிருந்தால், tester-கள் வருவதற்கு முன் அதைச் சரிசெய்யுங்கள்.

Test-ஐ அமையுங்கள்

  1. Closed track-ஐ உருவாக்குங்கள் அல்லது திறங்கள்: Test and release, பிறகு Testing, பிறகு Closed testing.
  2. உங்கள் tester-கள் வசிக்கும் நாடுகளைச் சேருங்கள்.
  3. Email பட்டியல் அல்லது Google Group மூலம் tester-களைச் சேருங்கள். Tester Exchange என்றால், testerexchange-testers@googlegroups.com-ஐச் சேருங்கள்.
  4. .aab-ஐப் பதிவேற்றி, release-ஐ review-க்கு அனுப்பி, அது Published என்று காட்டும் வரை காத்திருங்கள்.
  5. Opt-in link-ஐப் பகிருங்கள். முதல் முறை அது வேலை செய்யத் தொடங்க பல மணி நேரம் ஆகலாம்.

Tester-கள் “app not available” என்று தெரிவித்தால், அதைச் சரிசெய்வது பற்றிய வழிகாட்டியைப் பாருங்கள். தவறான கணக்குகள், நாடுகள், publish ஆகாத track-கள் ஆகியவற்றை அது விளக்குகிறது.

Tester-களை என்ன விளையாடச் சொல்வது

இரண்டு நிமிடத்துக்குள் முடியும் சிறிய தினசரி இலக்குகளை tester-களுக்குக் கொடுங்கள். உண்மையான, பல்வகை விளையாட்டுதான் உங்களுக்கு உதவும்; பிறகு production படிவத்தில் நீங்கள் விவரிக்கப் போவதும் அதைத்தான்.

  • நாட்கள் 1 முதல் 3: tutorial-ஐயும் முதல் level-ஐயும் முடிக்கச் சொல்லுங்கள். குழப்பமாக இருப்பதை எல்லாம் தெரிவிக்கச் சொல்லுங்கள்.
  • நாட்கள் 4 முதல் 7: தினமும் ஒரு குறுகிய session விளையாடுதல்; settings, ஒலி, கட்டுப்பாடுகள், pause ஆகியவற்றை முயற்சித்தல்.
  • நாட்கள் 8 முதல் 11: திருத்தங்களுடன் கூடிய புதிய build-ஐ முயற்சித்தல்; மேம்பட்டதா என்று பார்க்க ஒரு level-ஐ மீண்டும் விளையாடுதல்.
  • நாட்கள் 12 முதல் 14: கிடைக்கும் மிகக் கடினமான content-ஐ விளையாடி, crash, lag, battery வடிதல் ஆகியவற்றைத் தெரிவித்தல்.

உங்கள் கேமில் தினசரி பரிசுகள், குறுகிய தினசரி சவால் அல்லது விரைவு mode இருந்தால், tester-களை அதை நோக்கிச் செலுத்துங்கள். அது தினசரி வழக்கத்துடன் இயல்பாகப் பொருந்தும்.

ஈடுபாட்டைக் காட்டுங்கள்

  • Test நடக்கும்போது குறைந்தது ஒரு update, முடிந்தால் இரண்டு வெளியிடுங்கள். தெரிவிக்கப்பட்ட crash-ஐச் சரிசெய்வதே production படிவத்துக்குச் சிறந்த கதை.
  • உண்மையான சாதனங்களில் crash-கள் மற்றும் ANR-களைக் கண்டறிய Play Console-ல் Android vitals மற்றும் pre-launch report-ஐப் பயன்படுத்துங்கள்.
  • எளிய படிவத்தில் எழுத்துப்பூர்வக் கருத்துகளைச் சேகரியுங்கள்: சாதன மாடல், அவர்கள் என்ன செய்தனர், என்ன நடந்தது.
  • தினசரி செயலில் உள்ள tester-கள், session-கள், கண்டறிந்த bug-கள், வெளியிட்ட build-கள் ஆகியவற்றின் பதிவைப் பராமரியுங்கள்.

Multiplayer மற்றும் online கேம்கள்

உங்கள் கேமுக்கு server தேவை என்றால், 14 நாட்களும் அது இயங்கட்டும்; tester-கள் தனியாக இருக்கும்போதும் கேம் விளையாடக்கூடியதாக இருக்கட்டும். ஒருபோதும் நிரம்பாத lobby வெற்று test போலத் தெரியும். முடிந்தால் test காலத்துக்கு bot-கள் அல்லது தனி mode சேருங்கள்.

Sign-in தேவை என்றால், tester-களுக்கு வேலை செய்யும் guest mode அல்லது தெளிவான வழிமுறைகளைக் கொடுங்கள். Sign-in தடைகள் முதல் நாளே tester-களை இழக்கச் செய்யும்.

போதுமான players-ஐப் பெறுவது

12-க்குப் பதிலாக 15 tester-களைக் கேளுங்கள்; கேம்களில் சிலர் விரைவாக விலகிவிடுவார்கள். Tester Exchange தங்கள் சொந்த Android போன்களில் விளையாடும் உண்மையான மனிதர்களை அனுப்பி, ஒவ்வொரு tester-ன் தினசரிப் பயன்பாட்டையும் காட்டுகிறது: 12-க்கு $12.99, 15-க்கு $14.99, 25-க்கு $22.99, ஒருமுறை மட்டும் செலுத்த வேண்டும். https://testerexchange.com/earn-ல் மற்ற developer-களின் ஆப்கள் மற்றும் கேம்களை டெஸ்ட் செய்து tester-களை இலவசமாகவும் பெறலாம்.

அடிக்கடி கேட்கப்படும் கேள்விகள்

கேம்களுக்கும் closed testing தேவையா?

ஆம். 2023 நவம்பர் 13-க்குப் பிறகு உருவாக்கப்பட்ட personal கணக்குகளின் கேம்கள் உட்பட அனைத்து ஆப்களுக்கும் இந்தத் தேவை பொருந்தும்.

Closed testing-ன் போது என் கேம் முழுமையடையாமல் இருக்கலாமா?

ஆம், closed test என்பது பணி நடந்துகொண்டிருக்கும் ஆப்புக்கானது. ஆனால் tester-கள் இரண்டு வாரங்கள் விளையாடப் போதுமான content வேண்டும், test நடக்கும்போதும் நீங்கள் அதை மேம்படுத்திக்கொண்டே இருக்க வேண்டும்.

சில tester-களால் என் கேமை ஏன் install செய்ய முடியவில்லை?

பொதுவாக சாதன இணக்கம்தான் காரணம்: உயர்ந்த குறைந்தபட்ச Android பதிப்பு, 64-bit ஆதரவு இல்லாமை அல்லது தேவையான வன்பொருள் அம்சங்கள். Play Console-ல் Device catalog-ஐப் பாருங்கள்.

Tester-கள் தினமும் எவ்வளவு நேரம் விளையாட வேண்டும்?

Google எந்த எண்ணையும் நிர்ணயிக்கவில்லை. ஒருமுறை நீண்ட session விளையாடிவிட்டு பிறகு எதுவும் இல்லாமல் இருப்பதை விட, தினமும் ஒரு குறுகிய உண்மையான session சிறந்தது.

Test-க்கு Play Asset Delivery பயன்படுத்த வேண்டுமா?

உங்கள் கேம் பெரியதாக இருந்தால், ஆம். சிறிய முதல் பதிவிறக்கம் என்றால் அதிக tester-கள் உண்மையில் install செய்து விளையாடத் தொடங்குவார்கள்.

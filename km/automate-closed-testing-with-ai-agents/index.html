1. បង្កើត token

  1. ចូលគណនីនៅ https://testerexchange.com/api។
  2. បង្កើត token ផ្ទាល់ខ្លួន។ វាចាប់ផ្តើមដោយ tx_។ ចម្លងវាឥឡូវនេះ ហើយរក្សាទុកដូចពាក្យសម្ងាត់។
  3. Token អាចត្រូវបានដកហូតនៅពេលណាក៏បាន។ Token អាចចំណាយក្រេឌីតលើយុទ្ធនាការ ប៉ុន្តែវាមិនអាចទូទាត់ ដកលុយ ឬលុបគណនីរបស់អ្នកបានទេ។

2. ភ្ជាប់ MCP server

MCP server ប្រើ Streamable HTTP នៅ https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp។ ផ្ញើ token របស់អ្នកក្នុង header Authorization: Bearer tx_YOUR_TOKEN។

Claude Code៖ ដំណើរការពាក្យបញ្ជានេះម្តងក្នុង terminal របស់អ្នក។

claude mcp add --transport http tester-exchange https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp --header "Authorization: Bearer tx_YOUR_TOKEN"

Claude Desktop, Cursor, VS Code និង client ផ្សេងទៀតដែលមាន JSON config៖ បន្ថែម server ឈ្មោះ tester-exchange ជាមួយ type http, URL ខាងលើ និង headers entry ដែល Authorization កំណត់ជា Bearer tx_YOUR_TOKEN។ ទីតាំងឯកសារ config ពិតប្រាកដអាស្រ័យលើ client របស់អ្នក សូមពិនិត្យឯកសារ MCP របស់វា។

Client ដែលទទួលតែ URL (connector ChatGPT និងគេហទំព័រមួយចំនួន)៖ ឯកសារនៅ https://testerexchange.com/agents/ រាយទម្រង់ URL សម្រាប់ពួកគេ។ បើគ្មាន token ឧបករណ៍សាធារណៈ (Tester Exchange ជាអ្វី តម្លៃ ស្ថិតិវេទិកា) នៅតែដំណើរការ។

3. ឧបករណ៍តែមួយដើម្បីចាប់ផ្តើម៖ get_testers

អ្នកមិនចាំបាច់រៀនបញ្ជីឧបករណ៍ទាំងមូលទេ។ ឧបករណ៍សំខាន់គឺ get_testers(package_name, name?)។ ការហៅតែមួយបន្ថែមកម្មវិធីរបស់អ្នក បើកការសាកល្បងរបស់វា ប្រើក្រេឌីតរបស់អ្នក ហើយបញ្ជូនមកវិញនូវវឌ្ឍនភាពរបស់អ្នក ព្រមទាំងជំហានដែលមានតែមនុស្សប៉ុណ្ណោះដែលអាចធ្វើបាន ដូចជាការបន្ថែម Google Group ក្នុង Play Console។ ហៅវាម្តងទៀតនៅពេលណាក៏បានដើម្បីពិនិត្យវឌ្ឍនភាព។

ឧបករណ៍ផ្សេងទៀតគ្របដណ្តប់លម្អិត៖ my_apps, campaign_report (tester សកម្មភាពប្រចាំថ្ងៃ មតិកែលម្អ និងទិន្នន័យ production-access), add_testers, set_campaign_status (ផ្អាក បន្ត ឬបិទ ក្រេឌីតដែលមិនទាន់ប្រើត្រឡប់ទៅសមតុល្យរបស់អ្នក), share_kit និង buy_credits_links ដែលបញ្ជូនតំណទូទាត់ឱ្យមនុស្សបង់ប្រាក់។

HTTP API សម្រាប់ script និង CI

ប្រសិនបើឧបករណ៍របស់អ្នកមិនប្រើ MCP សូមប្រើ HTTP endpoint៖ POST https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call។ Body ជា JSON ដែលមាន p_token (token tx_ របស់អ្នក), p_action (ឧទាហរណ៍ help, my_apps ឬ start_campaign) និង p_args (ឧទាហរណ៍ package_name និងចំនួន tester)។ ផ្ញើ header apikey សាធារណៈដែលបង្ហាញក្នុងឯកសារ។

ហៅ action ឈ្មោះ help មុនគេ៖ វាបញ្ជូនមកវិញនូវ action ទាំងអស់ និង argument របស់វា។ Schema ពេញលេញនៅ https://testerexchange.com/openapi.json ដែលដំណើរការជាមួយ custom GPT actions របស់ ChatGPT និងឧបករណ៍ OpenAPI ផ្សេងទៀត។

A2A agent card

សម្រាប់ការរៀបចំ agent-to-agent, Tester Exchange បោះពុម្ព A2A agent card នៅ https://testerexchange.com/.well-known/agent-card.json។ Orchestrator ដែលគាំទ្រពិធីការ A2A អាចរកឃើញអ្វីដែល agent ផ្តល់ជូន និងរបៀបហៅវា។ ប្រើ token tx_ ដូចគ្នាសម្រាប់អ្វីៗដែលភ្ជាប់នឹងគណនីរបស់អ្នក។

ដំណើរការពេញលេញ ពីដើមដល់ចប់

  1. អ្នក upload .aab ដំបូងរបស់អ្នកទៅ closed track ក្នុង Play Console។
  2. Agent របស់អ្នកហៅ get_testers សម្រាប់ package name របស់អ្នក ហើយប្រាប់អ្នកឱ្យបន្ថែម testerexchange-testers@googlegroups.com ក្រោម Google Groups នៅលើ closed track។
  3. អ្នកបន្ថែមក្រុម រក្សាទុក ហើយត្រូវប្រាកដថា release ត្រូវបាន publish។
  4. ប្រសិនបើអ្នកខ្វះក្រេឌីត agent ផ្តល់តំណទូទាត់ឱ្យអ្នក។ អ្នកបង់ ($12.99 សម្រាប់ tester 12 នាក់, $14.99 សម្រាប់ 15 នាក់, $22.99 សម្រាប់ 25 នាក់) ឬរកក្រេឌីតដោយឥតគិតថ្លៃដោយសាកល្បងកម្មវិធីផ្សេងទៀតនៅ https://testerexchange.com/earn។
  5. Tester ពិតដំឡើង និងប្រើកម្មវិធីរបស់អ្នករយៈពេល 14 ថ្ងៃ។ Agent របស់អ្នកពិនិត្យវឌ្ឍនភាពរាល់ថ្ងៃ ហើយព្រមានអ្នកប្រសិនបើ tester សកម្មធ្លាក់ចុះ។
  6. នៅថ្ងៃទី 15 agent ទាញយករបាយការណ៍យុទ្ធនាការ ហើយព្រាងចម្លើយ production access របស់អ្នក។ អ្នកពិនិត្យវា ហើយចុច Apply for production។

Cursor ले Android एप बनाउनुभयो? 14 दिनका लागि आफ्ना 12 टेस्टर पाउनुहोस्

नोभेम्बर 2026 मा अपडेट गरिएको

Cursor ले तपाईंको Android एप लेख्न र बिल्ड गर्न सक्छ, तर Google Play ले माग्ने 12 वास्तविक टेस्टर दिन सक्दैन। तपाईंको व्यक्तिगत डेभलपर खाता 13 नोभेम्बर 2023 पछि बनेको हो भने, प्रोडक्सनका लागि आवेदन दिनुअघि कम्तीमा 12 टेस्टर लगातार 14 दिन जोडिएको क्लोज्ड टेस्ट चलाउनुपर्छ। यो गाइडमा बन्डल बनाउने, क्लोज्ड टेस्टिङ सुरु गर्ने, टेस्टर पाउने (पहिले निःशुल्क, दोस्रो सशुल्क) र Tester Exchange लाई Cursor सँग जोड्ने तरिका छ, ताकि एजेन्टले कागजी काम गरिदेओस्।

साँचा मान्छेहरूले आफ्नै फोनमा 14 दिन तपाईंको एप खोल्छन्। एकपटक तिर्नुहोस्, वा अरू एप टेस्ट गरेर निःशुल्क पाउनुहोस्।12 टेस्टर पाउनुहोस्
यो पेजमा
  • 1. रिलिज बन्डल (.aab) बनाउनुहोस्
  • 2. Play Console मा क्लोज्ड टेस्टिङ सुरु गर्नुहोस्
  • 3. आफ्ना 12 टेस्टर पाउनुहोस्: पहिले निःशुल्क, दोस्रो सशुल्क
  • 4. Tester Exchange लाई Cursor सँग जोड्नुहोस् (ऐच्छिक)
  • 5. एजेन्टलाई सोध्नुहोस्
  • MCP छैन? HTTP API प्रयोग गर्नुहोस्

1. रिलिज बन्डल (.aab) बनाउनुहोस्

  1. Cursor को एजेन्टलाई तपाईंको मोड्युलको build.gradle.kts मा रिलिज साइनिङ कन्फिगर गर्न भन्नुहोस् (storeFile, storePassword, keyAlias र keyPassword भएको signingConfigs ब्लक, release बिल्ड टाइपमा लागू गरिएको)। पासवर्ड git बाहिर राख्नुहोस् (Android का बिल्ड डक्स: https://developer.android.com/build/building-cmdline )।
  2. टर्मिनलमा ./gradlew bundleRelease चलाउनुहोस्। Gradle ले बन्डल बनाउँछ र साइन गर्छ; .aab सामान्यतया app/build/outputs/bundle/release/ मा देखिन्छ, तर आफ्नो बिल्ड आउटपुट जाँच गर्नुहोस्।
  3. कीस्टोर छैन भने keytool ले बनाउनुहोस् र ब्याकअप राख्नुहोस्। पहिलो रिलिज अपलोड गर्दा Google Play App Signing प्रस्ताव गरिन्छ।

2. Play Console मा क्लोज्ड टेस्टिङ सुरु गर्नुहोस्

  1. Test and release > Testing > Closed testing खोल्नुहोस्, अनि Create track (वा Manage track) मा क्लिक गर्नुहोस्।
  2. Create new release मा क्लिक गर्नुहोस्, .aab अपलोड गर्नुहोस्, रिलिजको नाम र नोट थप्नुहोस्, Save as draft, Next, अनि Start rollout (चरणहरू https://support.google.com/googleplay/android-developer/answer/9859348 बाट)।
  3. पहिले ड्यासबोर्डमा एप सेटअपका काम पूरा गर्नुहोस्, नत्र रिलिज बटन निष्क्रिय नै रहन्छ।

3. आफ्ना 12 टेस्टर पाउनुहोस्: पहिले निःशुल्क, दोस्रो सशुल्क

  • निःशुल्क बाटो: आफ्नो फोनमा https://testerexchange.com/earn खोल्नुहोस् र दिइएका एप टेस्ट गर्नुहोस्। तपाईंले टेस्ट गरेको हरेक एपले तपाईंको एपमा एक जना टेस्टर ल्याउँछ।
  • सशुल्क बाटो: एक पटक भुक्तानी गर्नुहोस् र टेस्टर आफैँ खटिन्छन्। हालका मूल्यहरू https://testerexchange.com/llms.txt मा सूचीबद्ध छन्।
  • 12 को सट्टा 15 टेस्टर मागिदिनुहोस्, ताकि एक जना छाडे पनि तपाईं Google को न्यूनतमभन्दा तल नपर्नुहोस्।

4. Tester Exchange लाई Cursor सँग जोड्नुहोस् (ऐच्छिक)

पहिले https://testerexchange.com/api मा API key बनाउनुहोस्। त्यसपछि यो आफ्नो प्रोजेक्टको .cursor/mcp.json मा राख्नुहोस्, वा सबै ठाउँमा प्रयोग गर्न ~/.cursor/mcp.json मा (फाइलका स्थान Cursor को MCP डक्सबाट, https://cursor.com/docs/context/mcp )। key कमिट नहोस् भनेर पहिले आफ्नो शेल एनभायरनमेन्टमा TESTER_EXCHANGE_KEY सेट गर्नुहोस्:

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Cursor ले url र headers फिल्डमा ${env:NAME} लाई मान बनाइदिन्छ। सर्भर लोड भएन भने Output प्यानल खोलेर MCP Logs छान्नुहोस्। सर्भर OAuth बिना Streamable HTTP मा चल्ने सादा MCP हो; सार्वजनिक टुलहरू (about, pricing, platform_stats) key बिना नै चल्छन्।

5. एजेन्टलाई सोध्नुहोस्

  • “Tester Exchange प्रयोग गरेर com.example.app का लागि 15 टेस्टर लिनू र Play Console मा मैले के गर्नुपर्छ भन्नू।”
  • “com.example.app का लागि मेरो Tester Exchange क्याम्पेन जाँचेर हिजो कति टेस्टर सक्रिय थिए भन्नू।”
  • “क्याम्पेन रिपोर्ट झिकेर वास्तविक अंकका आधारमा मेरा प्रोडक्सन एक्सेसका उत्तरको मस्यौदा बनाउनू।”

मुख्य टुल get_testers हो: यसले एप थप्छ, त्यसको टेस्ट खोल्छ र मान्छेले मात्र गर्न सक्ने चरणहरू फर्काउँछ, जस्तै Play Console मा टेस्टरहरूको Google ग्रुप थप्ने। एजेन्टले तपाईंको तर्फबाट भुक्तानी गर्न वा Apply for production मा क्लिक गर्न सक्दैन।

MCP छैन? HTTP API प्रयोग गर्नुहोस्

https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call मा POST गर्नुहोस्, https://testerexchange.com/agents/ मा सूचीबद्ध सार्वजनिक apikey हेडर र {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}} बडीसहित। स्किमा https://testerexchange.com/openapi.json मा छ। थप टुलहरू: https://testerexchange.com/guide/ai-builders/ ।

बारम्बार सोधिने प्रश्नहरू

के Cursor ले मेरो तर्फबाट 14 दिने टेस्ट पूरा गर्न सक्छ?

सक्दैन। 14 दिनका लागि आफ्नै Android फोनमा तपाईंको एप चलाउने वास्तविक मान्छे चाहिन्छ। Cursor ले एप बनाउन र सेटअप चलाउन सक्छ।

के Tester Exchange Cursor को आधिकारिक इन्टिग्रेसन हो?

होइन। यो स्वतन्त्र सेवा हो, जुन HTTP मार्फत रिमोट MCP समर्थन गर्ने जुनसुकै क्लाइन्टसँग चल्छ, र Cursor ले त्यो समर्थन गर्छ।

AAB कहाँ जान्छ?

यसलाई Play Console को क्लोज्ड टेस्टिङ रिलिजमा अपलोड गर्नुहोस्, अनि त्यही ट्र्याकमा आफ्ना टेस्टरहरूको Google ग्रुप वा इमेल सूची थप्नुहोस्।

12 टेस्टर पाउने निःशुल्क तरिका छ?

छ। https://testerexchange.com/earn मा अरू डेभलपरका एप टेस्ट गर्नुहोस्; तपाईंले टेस्ट गरेको हरेक एपले तपाईंको एपमा एक जना टेस्टर ल्याउँछ।

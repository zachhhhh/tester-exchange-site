用 AI 代理自動化 Google Play 封閉測試

2026 年 11 月更新

如果你已經讓 AI 代理協助寫程式，Google Play 封閉測試要求的大部分雜務也可以交給它：登錄你的應用程式、招募測試人員、檢查進度，以及整理正式版存取申請表要用的數據。Tester Exchange 為此提供 MCP 伺服器、單一端點的 HTTP API 和 A2A 代理卡。本指南說明如何連接 Claude Code、Claude Desktop、Cursor 等用戶端、可以問什麼，以及任何代理都無法代勞的部分。

真人在自己的手機上開啟你的應用程式，持續 14 天。付一次費，或免費測試其他應用程式。取得 12 位測試人員

代理能做與不能做的事

Google 要求 2023 年 11 月 13 日之後建立的個人開發人員帳戶，在申請正式版之前，必須先進行封閉測試，至少有 12 位測試人員連續 14 天維持選擇加入狀態。這中間大部分工作都是協調，正是代理擅長的。

  • 代理可以：新增你的應用程式、開啟測試人員活動、套用你的點數、查看有多少測試人員活躍、暫停或結束活動、取得每日活動報告，並依據報告協助草擬正式版存取的回答。
  • 必須由人完成：在 Play Console 把測試人員的 Google Group 加入封閉測試版本軌、發布版本、購買點數（結帳一律在真人的瀏覽器中進行），以及按下「申請正式版」。
  • 沒有人能自動化：14 天的真實使用。這要由真人在自己的 Android 手機上完成，這正是 Google 這項規定的重點。

1. 建立權杖

  1. 登入 https://testerexchange.com/api。
  2. 建立個人權杖。它以 tx_ 開頭。請立即複製，並像密碼一樣妥善保存。
  3. 權杖可隨時撤銷。權杖可以用點數建立活動，但不能付款、提款或刪除你的帳戶。

2. 連接 MCP 伺服器

MCP 伺服器使用 Streamable HTTP，位址為 https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp。請在標頭中帶上你的權杖：Authorization: Bearer tx_YOUR_TOKEN。

Claude Code：在終端機執行一次下列指令。

claude mcp add --transport http tester-exchange https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp --header "Authorization: Bearer tx_YOUR_TOKEN"

Claude Desktop、Cursor、VS Code 與其他使用 JSON 設定檔的用戶端：新增一個名為 tester-exchange 的伺服器，類型設為 http，填入上方的 URL，並加上 headers 項目，將 Authorization 設為 Bearer tx_YOUR_TOKEN。設定檔的確切位置因用戶端而異，請查閱該用戶端的 MCP 文件。

只接受 URL 的用戶端（部分 ChatGPT 和網頁連接器）：https://testerexchange.com/agents/ 的文件列出了適用的 URL 格式。沒有權杖時，公開工具（Tester Exchange 是什麼、價格、平台統計）仍然可以使用。

3. 從這一個工具開始：get_testers

你不必學會整個工具清單。主要工具是 get_testers(package_name, name?)。一次呼叫就能新增你的應用程式、開啟測試、套用你的點數，並回傳你的進度，以及只有真人能做的步驟，例如在 Play Console 加入 Google Group。隨時再呼叫一次即可查看進度。

其他工具負責處理細節：my_apps、campaign_report（測試人員、每日活動、意見回饋與正式版存取資料）、add_testers、set_campaign_status（暫停、繼續或結束；未使用的點數會退回你的餘額）、share_kit，以及 buy_credits_links（回傳結帳連結，由真人付款）。

好用的提示詞

  • 「幫 com.example.app 找 15 位測試人員，並告訴我在 Play Console 需要做什麼。」
  • 「查看我在 Tester Exchange 上 com.example.app 的活動。這週每天有多少測試人員活躍？」
  • 「取出活動報告並草擬我的正式版存取回答。只能使用真實數字。」
  • 「正式版存取已核准，現在請結束 com.example.app 的活動。」

請要求 15 位測試人員，而不是 12 位，這樣有人退出也不會讓你低於 Google 的最低要求。

給腳本與 CI 使用的 HTTP API

如果你的工具不支援 MCP，請使用 HTTP 端點：POST https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call。內容為 JSON，包含 p_token（你的 tx_ 權杖）、p_action（例如 help、my_apps 或 start_campaign）和 p_args（例如 package_name 和測試人員人數）。請帶上文件中提供的公開 apikey 標頭。

請先呼叫 help 動作：它會回傳所有動作與其參數。完整的結構描述位於 https://testerexchange.com/openapi.json，可搭配 ChatGPT 自訂 GPT 動作與其他 OpenAPI 工具使用。

A2A 代理卡

針對代理對代理的架構，Tester Exchange 在 https://testerexchange.com/.well-known/agent-card.json 發布了 A2A 代理卡。支援 A2A 協定的協調器可以探索這個代理提供的服務與呼叫方式。與你帳戶有關的操作，請使用同一組 tx_ 權杖。

從頭到尾的完整流程

  1. 你在 Play Console 把第一個 .aab 上傳到封閉測試版本軌。
  2. 你的代理針對你的套件名稱呼叫 get_testers，並告訴你在封閉測試版本軌的 Google Groups 下加入 testerexchange-testers@googlegroups.com。
  3. 你加入該群組、儲存，並確認版本已發布。
  4. 如果你的點數不足，代理會給你結帳連結。你可以付費（12 位測試人員 $12.99、15 位 $14.99、25 位 $22.99），或到 https://testerexchange.com/earn 測試其他應用程式，免費賺取點數。
  5. 真人測試人員安裝並使用你的應用程式 14 天。你的代理每天檢查進度，並在活躍測試人員減少時提醒你。
  6. 第 15 天，代理取出活動報告並草擬你的正式版存取回答。你檢查後按下「申請正式版」。

安全注意事項

  • 不要把權杖放進 git。請存放在用戶端的機密儲存區或環境變數中。
  • 我們這邊只儲存權杖的雜湊值，且每個帳戶最多 10 組權杖。不再使用的權杖請撤銷。
  • 提交前，請先檢查代理在你的正式版申請表中寫了什麼。Google 要求你如實描述你的測試。

常見問題

AI 代理可以幫我完成 14 天測試嗎？

不行。這 14 天需要真人在自己的手機上使用你的應用程式。代理負責設定、監控和報告。

代理可以幫我付費購買測試人員嗎？

不行。它可以回傳結帳連結，但付款一律在真人的瀏覽器中進行。

哪些用戶端可以使用 MCP 伺服器？

任何支援透過 Streamable HTTP 連接遠端 MCP 並可自訂標頭的用戶端，包括 Claude Code、Claude Desktop、Cursor 和 VS Code。其他用戶端可以使用 HTTP API。

在哪裡取得權杖？

登入後到 https://testerexchange.com/api。權杖以 tx_ 開頭，可隨時撤銷。

代理會更動我的 Play Console 嗎？

不會。它無法存取你的 Play Console，只會告訴你要在那邊做哪些步驟。

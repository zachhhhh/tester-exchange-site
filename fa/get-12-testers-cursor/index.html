Tester Exchange باز کردن Tester Exchange

اپ اندروید خود را با Cursor ساخته‌اید؟ ۱۲ تستر را برای ۱۴ روز بگیرید

به‌روزرسانی نوامبر ۲۰۲۶

Cursor می‌تواند اپ اندروید شما را بنویسد و بیلد کند، اما نمی‌تواند ۱۲ تستر واقعی مورد نیاز Google Play را فراهم کند. اگر حساب توسعه‌دهنده شخصی شما پس از ۱۳ نوامبر ۲۰۲۳ ساخته شده است، باید پیش از درخواست production یک تست بسته با دست‌کم ۱۲ تستر که ۱۴ روز پیوسته ثبت‌نام کرده‌اند اجرا کنید. این راهنما ساخت باندل، شروع تست بسته، گرفتن تستر (اول رایگان، بعد پولی) و اتصال Tester Exchange به Cursor را پوشش می‌دهد تا عامل کارهای اداری را انجام دهد.

آدم‌های واقعی اپ شما را 14 روز روی گوشی‌های خودشان باز می‌کنند. یک بار پرداخت کنید، یا با تست اپ‌های دیگر رایگان بگیرید.گرفتن 12 تستر

۱. باندل انتشار (.aab) را بسازید

  1. از عامل Cursor بخواهید امضای نسخه release را در build.gradle.kts ماژول شما تنظیم کند (بلوک signingConfigs با storeFile، storePassword، keyAlias و keyPassword، که روی build type از نوع release اعمال می‌شود). رمزها را از git دور نگه دارید (مستندات بیلد اندروید: https://developer.android.com/build/building-cmdline).
  2. در ترمینال ./gradlew bundleRelease را اجرا کنید. Gradle باندل را می‌سازد و امضا می‌کند؛ فایل .aab معمولاً در app/build/outputs/bundle/release/ ظاهر می‌شود، اما خروجی بیلد خودتان را بررسی کنید.
  3. اگر keystore ندارید با keytool یکی بسازید و از آن نسخه پشتیبان بگیرید. Google Play App Signing هنگام آپلود اولین نسخه به شما پیشنهاد می‌شود.

۲. تست بسته را در Play Console شروع کنید

  1. Test and release > Testing > Closed testing را باز کنید، سپس Create track (یا Manage track).
  2. روی Create new release بزنید، فایل .aab را آپلود کنید، نام و یادداشت‌های نسخه را اضافه کنید، Save as draft، Next و سپس Start rollout (مراحل از https://support.google.com/googleplay/android-developer/answer/9859348).
  3. ابتدا کارهای راه‌اندازی اپ را در Dashboard کامل کنید، وگرنه دکمه انتشار غیرفعال می‌ماند.

۳. ۱۲ تستر خود را بگیرید: اول رایگان، بعد پولی

  • راه رایگان: https://testerexchange.com/earn را در گوشی باز کنید و اپ‌هایی را که به شما داده می‌شود تست کنید. هر اپی که تست می‌کنید یک تستر برای اپ شما می‌آورد.
  • راه پولی: یک بار پرداخت کنید و تسترها خودکار تخصیص داده می‌شوند. قیمت‌های فعلی در https://testerexchange.com/llms.txt آمده است.
  • به‌جای ۱۲ تستر، ۱۵ تستر بخواهید تا اگر یک نفر انصراف داد، شما زیر حداقل Google نمانید.

۴. Tester Exchange را به Cursor وصل کنید (اختیاری)

ابتدا در https://testerexchange.com/api یک کلید API بسازید. سپس این را در .cursor/mcp.json در پروژه خود بگذارید، یا در ~/.cursor/mcp.json تا همه‌جا استفاده شود (مکان فایل‌ها طبق مستندات MCP در Cursor، https://cursor.com/docs/context/mcp). ابتدا TESTER_EXCHANGE_KEY را در محیط shell خود تنظیم کنید تا کلید commit نشود:

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Cursor مقدار ${env:NAME} را در فیلدهای url و headers جایگزین می‌کند. اگر سروری بارگذاری نشد، پنل Output را باز کنید و MCP Logs را انتخاب کنید. سرور یک MCP ساده روی Streamable HTTP و بدون OAuth است؛ ابزارهای عمومی (about، pricing، platform_stats) بدون کلید کار می‌کنند.

۵. از عامل بخواهید

  • «از Tester Exchange استفاده کن و ۱۵ تستر برای com.example.app بگیر و بگو در Play Console چه کاری باید انجام دهم.»
  • «کمپین Tester Exchange من برای com.example.app را بررسی کن و بگو دیروز چند تستر فعال بودند.»
  • «گزارش کمپین را بگیر و بر اساس اعداد واقعی پیش‌نویس پاسخ‌های درخواست دسترسی production را بنویس.»

ابزار اصلی get_testers است: اپ را اضافه می‌کند، تست آن را باز می‌کند و مراحلی را که فقط انسان می‌تواند انجام دهد برمی‌گرداند، مثل افزودن Google Group تسترها در Play Console. عامل نمی‌تواند پرداخت کند یا به جای شما روی Apply for production کلیک کند.

MCP ندارید؟ از API نوع HTTP استفاده کنید

یک POST به https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call بفرستید با هدر apikey عمومی که در https://testerexchange.com/agents/ آمده و بدنه {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}}. طرحواره در https://testerexchange.com/openapi.json است. ابزارهای بیشتر: https://testerexchange.com/guide/ai-builders/.

پرسش‌های متداول

آیا Cursor می‌تواند تست ۱۴ روزه را برای من انجام دهد؟

خیر. آن ۱۴ روز به آدم‌های واقعی نیاز دارد که اپ شما را روی گوشی‌های اندرویدی خودشان استفاده کنند. Cursor می‌تواند اپ را بسازد و راه‌اندازی را پیش ببرد.

آیا Tester Exchange یکپارچه‌سازی رسمی Cursor است؟

خیر. این یک سرویس مستقل است که با هر کلاینتی که از MCP راه دور روی HTTP پشتیبانی کند کار می‌کند، و Cursor چنین پشتیبانی‌ای دارد.

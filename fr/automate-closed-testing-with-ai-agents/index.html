Automatiser le test fermé Google Play avec des agents IA

Mis à jour en novembre 2026

Si vous livrez déjà du code avec un agent IA, vous pouvez aussi lui confier l'essentiel des tâches fastidieuses du test fermé exigé par Google Play : référencer votre appli, recruter des testeurs, suivre l'avancement et récupérer les chiffres pour le formulaire d'accès à la production. Tester Exchange propose pour cela un serveur MCP, une API HTTP à point d'entrée unique et une fiche d'agent A2A. Ce guide montre comment connecter Claude Code, Claude Desktop, Cursor et d'autres clients, quoi demander, et ce qu'aucun agent ne peut faire à votre place.

Ce qu'un agent peut et ne peut pas faire

Google exige que les comptes de développeur personnels créés après le 13 novembre 2023 mènent un test fermé avec au moins 12 testeurs inscrits pendant 14 jours consécutifs avant de demander la production. L'essentiel du travail autour de cela est de la coordination, ce que les agents font bien.

  • Un agent peut : ajouter votre appli, ouvrir une campagne de testeurs, appliquer vos crédits, vérifier combien de testeurs sont actifs, mettre en pause ou clore une campagne, récupérer le rapport d'activité quotidienne et vous aider à rédiger les réponses du formulaire d'accès à la production à partir de ce rapport.
  • Un humain doit : ajouter le Google Group des testeurs au canal de test fermé dans la Play Console, publier la version, acheter des crédits (le paiement se fait toujours dans le navigateur d'une personne) et cliquer sur Demander l'accès à la production.
  • Personne ne peut automatiser : les 14 jours d'utilisation réelle. Ils sont assurés par de vraies personnes sur leur propre téléphone Android, ce qui est tout l'objet de la règle de Google.

1. Créer un jeton

  1. Connectez-vous sur https://testerexchange.com/api.
  2. Créez un jeton personnel. Il commence par tx_. Copiez-le maintenant et conservez-le comme un mot de passe.
  3. Les jetons peuvent être révoqués à tout moment. Un jeton peut dépenser des crédits pour des campagnes, mais il ne peut pas payer, retirer de l'argent ni supprimer votre compte.

2. Connecter le serveur MCP

Le serveur MCP utilise Streamable HTTP à l'adresse https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp. Envoyez votre jeton dans l'en-tête Authorization: Bearer tx_YOUR_TOKEN.

Claude Code : exécutez cette commande une fois dans votre terminal.

claude mcp add --transport http tester-exchange https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp --header "Authorization: Bearer tx_YOUR_TOKEN"

Claude Desktop, Cursor, VS Code et autres clients avec configuration JSON : ajoutez un serveur nommé tester-exchange de type http, avec l'URL ci-dessus et une entrée headers où Authorization vaut Bearer tx_YOUR_TOKEN. L'emplacement exact du fichier de configuration dépend de votre client ; consultez sa documentation MCP.

Clients qui n'acceptent qu'une URL (certains connecteurs ChatGPT et web) : la documentation sur https://testerexchange.com/agents/ propose une forme d'URL pour eux. Sans jeton, les outils publics (présentation de Tester Exchange, tarifs, statistiques de la plateforme) fonctionnent quand même.

3. L'outil pour commencer : get_testers

Inutile d'apprendre toute la liste d'outils. L'outil principal est get_testers(package_name, name?). Un seul appel ajoute votre appli, ouvre son test, applique vos crédits et renvoie votre progression ainsi que les étapes que seul un humain peut faire, comme ajouter le Google Group dans la Play Console. Rappelez-le à tout moment pour suivre l'avancement.

D'autres outils couvrent le détail : my_apps, campaign_report (testeurs, activité quotidienne, retours et données pour l'accès à la production), add_testers, set_campaign_status (pause, reprise ou clôture ; les crédits inutilisés sont remis sur votre solde), share_kit et buy_credits_links, qui renvoie des liens de paiement qu'un humain doit régler.

Des demandes qui fonctionnent

  • « Obtiens 15 testeurs pour com.example.app et dis-moi ce que je dois faire dans la Play Console. »
  • « Vérifie ma campagne Tester Exchange pour com.example.app. Combien de testeurs étaient actifs chaque jour cette semaine ? »
  • « Récupère le rapport de campagne et rédige mes réponses pour l'accès à la production. Utilise uniquement les vrais chiffres. »
  • « Clos la campagne de com.example.app maintenant que l'accès à la production est approuvé. »

Demandez 15 testeurs plutôt que 12, pour qu'un abandon ne vous fasse pas passer sous le minimum de Google.

API HTTP pour scripts et CI

Si votre outil ne parle pas MCP, utilisez le point d'entrée HTTP : POST https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call. Le corps est du JSON avec p_token (votre jeton tx_), p_action (par exemple help, my_apps ou start_campaign) et p_args (par exemple un package_name et un nombre de testeurs). Envoyez l'en-tête public apikey indiqué dans la documentation.

Appelez d'abord l'action help : elle renvoie toutes les actions et leurs arguments. Le schéma complet est sur https://testerexchange.com/openapi.json, compatible avec les actions de GPT personnalisés de ChatGPT et d'autres outils OpenAPI.

Fiche d'agent A2A

Pour les architectures agent à agent, Tester Exchange publie une fiche d'agent A2A à l'adresse https://testerexchange.com/.well-known/agent-card.json. Les orchestrateurs compatibles avec le protocole A2A peuvent y découvrir ce que l'agent propose et comment l'appeler. Utilisez le même jeton tx_ pour tout ce qui est lié à votre compte.

Un déroulé complet, du début à la fin

  1. Vous importez votre premier .aab sur le canal de test fermé dans la Play Console.
  2. Votre agent appelle get_testers avec votre nom de package et vous dit d'ajouter testerexchange-testers@googlegroups.com sous Google Groups sur le canal de test fermé.
  3. Vous ajoutez le groupe, enregistrez et vous assurez que la version est publiée.
  4. Si vous manquez de crédits, l'agent vous donne un lien de paiement. Vous payez (12,99 $ pour 12 testeurs, 14,99 $ pour 15, 22,99 $ pour 25) ou gagnez des crédits gratuitement en testant d'autres applis sur https://testerexchange.com/earn.
  5. De vrais testeurs installent et utilisent votre appli pendant 14 jours. Votre agent vérifie l'avancement chaque jour et vous prévient si le nombre de testeurs actifs baisse.
  6. Le jour 15, l'agent récupère le rapport de campagne et rédige vos réponses pour l'accès à la production. Vous les relisez et cliquez sur Demander l'accès à la production.

Conseils de sécurité

  • Ne mettez pas vos jetons dans git. Placez-les dans le stockage de secrets de votre client ou dans une variable d'environnement.
  • De notre côté, les jetons ne sont stockés que sous forme de hachage et sont limités à 10 par compte. Révoquez tout jeton que vous n'utilisez plus.
  • Relisez ce que l'agent écrit dans votre formulaire de production avant de l'envoyer. Google vous demande de décrire votre test avec honnêteté.

Questions fréquentes

Un agent IA peut-il effectuer le test de 14 jours à ma place ?

Non. Les 14 jours exigent de vraies personnes qui utilisent votre appli sur leur propre téléphone. Les agents s'occupent de la configuration, du suivi et des rapports.

L'agent peut-il payer les testeurs ?

Non. Il peut renvoyer des liens de paiement, mais le paiement se fait toujours dans le navigateur d'un humain.

Quels clients fonctionnent avec le serveur MCP ?

Tout client qui prend en charge le MCP distant via Streamable HTTP avec un en-tête personnalisé, dont Claude Code, Claude Desktop, Cursor et VS Code. Les autres peuvent utiliser l'API HTTP.

Où obtenir un jeton ?

Sur https://testerexchange.com/api après connexion. Les jetons commencent par tx_ et peuvent être révoqués à tout moment.

L'agent modifie-t-il quelque chose dans ma Play Console ?

Non. Il n'a aucun accès à votre Play Console. Il vous indique les étapes à y effectuer.

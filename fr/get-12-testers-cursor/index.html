Application Android créée avec Cursor ? Obtenez vos 12 testeurs pour 14 jours

Mis à jour en novembre 2026

Cursor peut écrire et compiler votre application Android, mais il ne peut pas fournir les 12 vrais testeurs exigés par Google Play. Si votre compte développeur personnel a été créé après le 13 novembre 2023, vous devez mener un test fermé avec au moins 12 testeurs inscrits pendant 14 jours consécutifs avant de demander la production. Ce guide couvre la génération du bundle, le lancement du test fermé, l'obtention des testeurs (gratuit d'abord, payant ensuite) et la connexion de Tester Exchange à Cursor pour que l'agent s'occupe des démarches.

1. Générer le bundle de version (.aab)

  1. Demandez à l'agent de Cursor de configurer la signature de version dans le build.gradle.kts de votre module (un bloc signingConfigs avec storeFile, storePassword, keyAlias et keyPassword, appliqué au type de build release). Gardez les mots de passe hors de git (documentation Android : https://developer.android.com/build/building-cmdline).
  2. Exécutez ./gradlew bundleRelease dans le terminal. Gradle compile et signe le bundle ; le .aab apparaît normalement dans app/build/outputs/bundle/release/, mais vérifiez la sortie de votre propre build.
  3. Créez un keystore avec keytool si vous n'en avez pas, et sauvegardez-le. Google Play App Signing vous est proposé lors de l'importation de votre première version.

2. Lancer le test fermé dans la Play Console

  1. Ouvrez Tester et publier > Tests > Test fermé, puis Créer un canal (ou Gérer le canal).
  2. Cliquez sur Créer une release, importez le .aab, ajoutez un nom de release et des notes, Enregistrer comme brouillon, Suivant, puis Lancer le déploiement (étapes tirées de https://support.google.com/googleplay/android-developer/answer/9859348).
  3. Terminez d'abord les tâches de configuration de l'application dans le Tableau de bord, sinon le bouton de release reste désactivé.

3. Obtenir vos 12 testeurs : gratuit d'abord, payant ensuite

  • Voie gratuite : ouvrez https://testerexchange.com/earn sur votre téléphone et testez les applications qui vous sont attribuées. Chaque application que vous testez apporte un testeur à la vôtre.
  • Voie payante : payez une fois et les testeurs sont attribués automatiquement. Les prix actuels sont indiqués sur https://testerexchange.com/llms.txt.
  • Demandez 15 testeurs plutôt que 12, afin qu'un abandon ne vous laisse pas sous le minimum de Google.

4. Connecter Tester Exchange à Cursor (facultatif)

Créez d'abord une clé API sur https://testerexchange.com/api. Placez ensuite ceci dans .cursor/mcp.json dans votre projet, ou dans ~/.cursor/mcp.json pour l'utiliser partout (emplacements des fichiers d'après la documentation MCP de Cursor, https://cursor.com/docs/context/mcp). Définissez d'abord TESTER_EXCHANGE_KEY dans l'environnement de votre shell, afin que la clé ne soit pas commitée :

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Cursor résout ${env:NAME} dans les champs url et headers. Si un serveur ne se charge pas, ouvrez le panneau Output et choisissez MCP Logs. Le serveur est du MCP simple sur Streamable HTTP sans OAuth ; les outils publics (about, pricing, platform_stats) fonctionnent sans clé.

5. Interroger l'agent

  • « Utilise Tester Exchange pour obtenir 15 testeurs pour com.example.app et dis-moi ce que je dois faire dans la Play Console. »
  • « Vérifie ma campagne Tester Exchange pour com.example.app et dis-moi combien de testeurs étaient actifs hier. »
  • « Récupère le rapport de campagne et rédige mes réponses pour l'accès à la production à partir des vrais chiffres. »

L'outil principal est get_testers : il ajoute l'application, ouvre son test et renvoie les étapes que seul un humain peut accomplir, comme ajouter le Google Group des testeurs dans la Play Console. L'agent ne peut ni payer ni cliquer sur Demander l'accès à la production à votre place.

Pas de MCP ? Utilisez l'API HTTP

Faites un POST sur https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call avec l'en-tête apikey public indiqué sur https://testerexchange.com/agents/ et le corps {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}}. Le schéma se trouve sur https://testerexchange.com/openapi.json. Autres outils : https://testerexchange.com/guide/ai-builders/.

Questions fréquentes

Cursor peut-il réaliser le test de 14 jours à ma place ?

Non. Les 14 jours exigent de vraies personnes qui utilisent votre application sur leurs propres téléphones Android. Cursor peut créer l'application et piloter la configuration.

Tester Exchange est-il une intégration officielle de Cursor ?

Non. C'est un service indépendant qui fonctionne avec tout client prenant en charge le MCP distant via HTTP, ce que fait Cursor.

Où va l'AAB ?

Importez-le dans une release de test fermé dans la Play Console, puis ajoutez le Google Group ou la liste d'e-mails de vos testeurs sur ce canal.

Existe-t-il un moyen gratuit d'obtenir les 12 testeurs ?

Oui. Testez les applications d'autres développeurs sur https://testerexchange.com/earn ; chaque application que vous testez apporte un testeur à la vôtre.

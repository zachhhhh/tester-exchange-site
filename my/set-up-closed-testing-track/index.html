Play Console တွင် closed testing track ကို အဆင့်ဆင့် setup လုပ်နည်း

2026 နိုဝင်ဘာတွင် update လုပ်ထားသည်

သင့် ၁၄ ရက်နာရီ မစတင်မီ publish လုပ်ပြီးသော၊ tester များ ချိတ်ဆက်ထားပြီးသော၊ အလုပ်လုပ်သော opt-in link ပေးသည့် closed testing track တစ်ခု လိုအပ်သည်။ နောက်ပိုင်း ပြဿနာအများစု၊ ဥပမာ tester များ "app not available" မြင်ခြင်းသည် ဤနေရာတွင် ကျန်ခဲ့သော အဆင့်တစ်ခုကြောင့် ဖြစ်သည်။ ဤလမ်းညွှန်သည် လက်ရှိ Play Console menu များ (Test and release → Testing → Closed testing) နှင့် Google ၏ Help Center ကို လိုက်နာထားသည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်
ဤစာမျက်နှာတွင်
  • မစတင်မီ
  • ၁။ Closed track ကို ဖွင့်ပါ သို့မဟုတ် ဖန်တီးပါ
  • ၂။ နိုင်ငံနှင့် ဒေသများ ရွေးပါ
  • ၃။ Tester များ ထည့်ပါ: email list သို့မဟုတ် Google Group
  • ၄။ Feedback channel တစ်ခု ထည့်ပါ
  • ၅။ Release ဖန်တီးပြီး review သို့ ပို့ပါ
  • ၆။ Opt-in link ကို မျှဝေပါ
  • ၇။ ၁၄ ရက် ရေတွက်နေကြောင်း စစ်ပါ
  • မကြာခဏ မေးလေ့ရှိသော မေးခွန်းများ

မစတင်မီ

  • ကိုယ်ပိုင်အတည်ပြုခြင်း ပြီးဆုံးသော Play Console developer account။
  • Store listing၊ content rating၊ target audience၊ data safety နှင့် အခြား App content declaration များ ဖြည့်ပြီးသော Play Console တွင် ဖန်တီးထားသည့် သင့် app။ လိုအပ်သော အချက်များ ကျန်နေစဉ် release ကို review သို့ ပို့ရန် Play Console က ခွင့်မပြုပါ။
  • ထာဝရထားလိုသည့် package name ပါသော sign လုပ်ထားသည့် Android App Bundle (.aab)။ နောက်ပိုင်း ပြောင်း၍မရပါ။
  • သင့် tester များအတွက် အစီအစဉ်: Android ဖုန်းနှင့် Google Account ရှိသော လူအစစ် အနည်းဆုံး ၁၂ ယောက်၊ အကောင်းဆုံး ၁၅ ယောက်။

၁။ Closed track ကို ဖွင့်ပါ သို့မဟုတ် ဖန်တီးပါ

  1. Play Console တွင် သင့် app ကို ရွေးပါ။
  2. Test and release → Testing → Closed testing သို့ သွားပါ။
  3. Play Console က default closed track (မကြာခဏ Alpha ဟုခေါ်) ပေးသည်။ ၎င်းကို သုံးပါ။ ထပ်ဆောင်း closed track များ ဖန်တီးနိုင်သော်လည်း လိုအပ်ချက်အတွက် တစ်ခုပဲ လုံလောက်သည်။
  4. Manage track ကို နှိပ်ပါ။

၂။ နိုင်ငံနှင့် ဒေသများ ရွေးပါ

Countries / regions tab ကိုဖွင့်ပြီး သင့် tester များ နေထိုင်ရာ နိုင်ငံများကို ထည့်ပါ။ သင်မရွေးထားသော နိုင်ငံရှိ tester က app ကို install မလုပ်နိုင်ပါ။

ဖြန့်ချိသော နိုင်ငံများ၏ ပြောင်းလဲမှုများသည် track များအားလုံးတွင် သက်ရောက်ပြီး ထပ်ဆောင်း closed track များတွင် ကိုယ်ပိုင် နိုင်ငံရွေးချယ်မှုကို မပံ့ပိုးကြောင်း Google က မှတ်ချက်ပြုသည်။ သင့် tester များ ကမ္ဘာအနှံ့ရှိလျှင် အရိုးရှင်းဆုံးရွေးချယ်မှုမှာ တရားဝင်ပို့နိုင်သည့် နိုင်ငံအားလုံးကို ထည့်ခြင်းဖြစ်သည်။

၃။ Tester များ ထည့်ပါ: email list သို့မဟုတ် Google Group

Testers tab ကိုဖွင့်ပါ။ ရွေးချယ်စရာ နှစ်ခုရှိပြီး track တစ်ခုတည်းတွင် နှစ်ခုလုံးသုံးနိုင်သည်။

  • Email list: Create email list ကိုနှိပ်ပြီး အမည်ပေးကာ လိပ်စာများ ရိုက်ထည့်ပါ သို့မဟုတ် CSV upload လုပ်ပါ။ Google က list တစ်ခုလျှင် အသုံးပြုသူ ၂,၀၀၀ အထိ ခွင့်ပြုသည်။ CSV upload လုပ်ခြင်းက ထို list ထဲရှိပြီးသား လိပ်စာများကို ထပ်ရေးသည်။ လိပ်စာတိုင်းသည် tester က ၎င်း၏ဖုန်းရှိ Play Store တွင် သုံးသော Google Account ဖြစ်ရမည်။
  • Google Group: group ၏ လိပ်စာ၊ ဥပမာ yourgroup@googlegroups.com ကို ထည့်ပါ။ Group ၏ member များသာ သင့် test တွင် ပါဝင်နိုင်ပြီး opt in မလုပ်မီ group သို့ ဝင်ရမည်။ Group ထဲသို့ လူထည့်ရုံသာ လုပ်ရပြီး Play Console ကို ထပ်မထိရပါ။

Tester Exchange သုံးလျှင် Google Groups အောက်တွင် group testerexchange-testers@googlegroups.com ကို ထည့်ပြီး သိမ်းပါ။ ထိုလိပ်စာတစ်ခုတည်းက ကျွန်ုပ်တို့ပို့သော tester တိုင်းကို သင့် app install လုပ်ခွင့်ပေးသည်။ Google Group နှင့် email list ကွာခြားချက် လမ်းညွှန်ကိုလည်း ကြည့်ပါ။

၄။ Feedback channel တစ်ခု ထည့်ပါ

တူညီသော Testers tab တွင် feedback URL သို့မဟုတ် email လိပ်စာတစ်ခု ထည့်ပါ။ Tester များ ဝင်လာသောအခါ ၎င်းကို မြင်ရသည်။ Production access form တွင် tester feedback ကို အကျဉ်းချုပ်ရမည်ဖြစ်သောကြောင့် လွယ်ကူအောင်လုပ်ပါ: Google Form တိုတစ်ခု သို့မဟုတ် သီးသန့် email လိပ်စာက အလုပ်ဖြစ်သည်။

၅။ Release ဖန်တီးပြီး review သို့ ပို့ပါ

  1. Closed track တွင် Create new release ကို နှိပ်ပါ။
  2. .aab ကို upload လုပ်ပါ။ အကြောင်းမရှိလျှင် သင့် key ကို Play App Signing က စီမံခွင့်ပေးပါ။
  3. Release အမည်နှင့် release note တိုတစ်ခု ထည့်ပါ၊ ဥပမာ "First closed test build"။
  4. Next ကိုနှိပ်ပြီး error များကိုပြင်ကာ Save လုပ်ပါ။
  5. Publishing overview သို့သွားပြီး ပြောင်းလဲမှုများကို review သို့ ပို့ပါ။ Managed publishing ဖွင့်ထားလျှင် အတည်ပြုပြီးနောက် Publish ကိုလည်း နှိပ်ရမည်။

Account အသစ်များရှိ closed test release များကို live မဖြစ်မီ review လုပ်သည်။ အချိန်သည် နာရီအနည်းငယ်မှ ရက်များစွာအထိ ကွဲပြားသည်။

၆။ Opt-in link ကို မျှဝေပါ

App အခြေအနေ Published ဖြစ်မှသာ opt-in link ပေါ်လာသည်ဟု Google က ဆိုသည်။ Testers tab မှ copy ကူးပါ။ ၎င်းသည် https://play.google.com/apps/testing/your.package.name ကဲ့သို့ ဖြစ်သည်။

ပထမဆုံး publish လုပ်ချိန်တွင် link အလုပ်လုပ်စတင်ရန် နာရီများစွာ ကြာနိုင်သည်။ Tester များသည် Google Play တွင် ရှာ၍ closed test များကို မတွေ့နိုင်သောကြောင့် ဤ link သို့မဟုတ် သင့် app ၏ Play Store link လိုအပ်သည်။

  1. Tester က သင်ထည့်ထားသော (သို့မဟုတ် သင့် Google Group ထဲရှိ) Google Account တူတူဖြင့် sign in ဝင်သည်။
  2. Opt-in link ကိုဖွင့်ပြီး tester ဖြစ်ရန် နှိပ်သည်။
  3. ထိုစာမျက်နှာပေါ်ရှိ link ကိုသုံးပြီး Google Play မှ သင့် app ကို install လုပ်သည်။
  4. App ကိုဖွင့်ပြီး ၁၄ ရက်အတွင်း ဆက်ဖွင့်သည်။

၇။ ၁၄ ရက် ရေတွက်နေကြောင်း စစ်ပါ

သင့် Dashboard က closed testing လိုအပ်ချက်နှင့် tester မည်မျှ opt in ထားသည်ကို ပြသည်။ နှစ်ရက်သုံးရက်တစ်ကြိမ် စစ်ပါ။ အရေအတွက် ၁၂ အောက်ကျလျှင် လိုအပ်ချက်က ဆက်တိုက် opt in ထားသော tester ၁၂ ယောက်ကို ရေတွက်သောကြောင့် အစားထိုးသူများကို ချက်ချင်း ရှာပါ။

Test အတွင်း တူညီသော track သို့ build အသစ် အနည်းဆုံးတစ်ခု upload လုပ်ပါ။ Feedback အပေါ် သင်လုပ်ဆောင်ခဲ့ကြောင်း Google ကို ပြသပြီး track ပေါ်ရှိ tester များက update ကို အလိုအလျောက် ရရှိသည်။

မကြာခဏ မေးလေ့ရှိသော မေးခွန်းများ

Internal testing ကို အစားထိုး သုံးနိုင်သလား?

မရပါ။ လိုအပ်ချက်အတွက် closed test လိုအပ်သည်။ သင့် internal test တွင် opt in လုပ်ထားသူများသည် internal ထဲမှ မထွက်မချင်း closed test သို့ မဝင်နိုင်ကြောင်းလည်း Google က ဆိုသည်။

Email list သုံးသင့်သလား၊ Google Group သုံးသင့်သလား?

Tester များ ဝင်လိုက်ထွက်လိုက်ရှိလျှင် Google Group က ပိုလွယ်သည်၊ track ကို ဘယ်တော့မှ မပြင်ရပါ။ ပုံသေ မိတ်ဆွေအုပ်စုအတွက်မူ email list ကောင်းသည်။ နှစ်ခုလုံးကိုလည်း သုံးနိုင်သည်။

Opt-in link ကို ဘာကြောင့် မမြင်ရတာလဲ?

Closed track ပေါ်ရှိ release ကို publish လုပ်မှသာ ပေါ်လာသည်။ Publishing overview တွင် review စောင့်နေခြင်း သို့မဟုတ် မပို့ရသေးသော ပြောင်းလဲမှုများ ရှိမရှိ စစ်ပါ။

Tester တစ်ယောက်ကို Google Account လိုအပ်သလား?

လိုအပ်သည်။ Test တွင်ပါဝင်ရန် အသုံးပြုသူများသည် Google Account သို့မဟုတ် Google Workspace account လိုအပ်ပြီး ၎င်းသည် ၎င်းတို့ဖုန်းရှိ Play Store ပေါ်ရှိ account ဖြစ်ရမည်ဟု Google က ဆိုသည်။

Closed test app ကို ငွေပေးရသော app ဖြစ်အောင် လုပ်နိုင်သလား?

လုပ်နိုင်သော်လည်း closed test များတွင် tester များက ငွေပေးရသော app များကို ဝယ်ရမည်ဟု Google က ဆိုသည်။ Tester များ မဆုံးရှုံးစေရန် test app ကို အခမဲ့ထားပါ။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်

  • App Inventor၊ Kodular၊ Flutter၊ Unity နှင့် အခြား tool များဖြင့် ဖန်တီးထားသော app များအတွက် Google Play tester ၁၂ ယောက်
  • Google Play closed tester များအတွက် "app not available" ကို ပြင်နည်း
  • AI agent များဖြင့် Google Play closed testing ကို automate လုပ်ပါ
  • How to become an Android app tester

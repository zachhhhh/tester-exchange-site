Tester Exchange Tester Exchange ကို ဖွင့်ရန်

Cursor ဖြင့် Android app ဆောက်ပြီးပြီလား။ tester ၁၂ ဦးကို ၁၄ ရက် ရယူပါ

၂၀၂၆ ခုနှစ် နိုဝင်ဘာလတွင် ပြင်ဆင်ထားသည်

Cursor က သင့် Android app ကို ရေးပြီး build လုပ်ပေးနိုင်သော်လည်း Google Play လိုအပ်သည့် တကယ့် tester ၁၂ ဦးကို မပေးနိုင်ပါ။ သင့်ကိုယ်ပိုင်ဒေဗလပ်ပါအကောင့်ကို ၂၀၂၃ ခုနှစ် နိုဝင်ဘာ ၁၃ ရက်နောက်ပိုင်း ဖန်တီးထားလျှင် production သို့ မလျှောက်မီ tester အနည်းဆုံး ၁၂ ဦး ၁၄ ရက်ဆက်တိုက် opt in လုပ်ထားသော closed test တစ်ခု ပြေးရမည်။ ဤလမ်းညွှန်တွင် bundle ဆောက်ခြင်း၊ closed testing စတင်ခြင်း၊ tester ရယူခြင်း (အခမဲ့အရင်၊ ငွေပေးနောက်) နှင့် agent က စာရွက်စာတမ်းအလုပ်ကို လုပ်နိုင်ရန် Tester Exchange ကို Cursor နှင့် ချိတ်ဆက်ခြင်းတို့ ပါဝင်သည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်
ဤစာမျက်နှာတွင်
  • ၁။ release bundle (.aab) ကို ဆောက်ပါ
  • ၂။ Play Console တွင် closed testing စတင်ပါ
  • ၃။ tester ၁၂ ဦးကို ရယူပါ- အခမဲ့အရင်၊ ငွေပေးနောက်
  • ၄။ Tester Exchange ကို Cursor နှင့် ချိတ်ဆက်ပါ (ရွေးချယ်စရာ)
  • ၅။ agent ကို မေးပါ
  • MCP မရှိဘူးလား။ HTTP API ကို သုံးပါ
  • မေးလေ့ရှိသော မေးခွန်းများ

၁။ release bundle (.aab) ကို ဆောက်ပါ

  1. သင့် module ၏ build.gradle.kts တွင် release signing ကို ပြင်ဆင်ရန် Cursor ၏ agent ကို တောင်းဆိုပါ (release build type တွင် သတ်မှတ်ထားသော storeFile၊ storePassword၊ keyAlias နှင့် keyPassword ပါသော signingConfigs block)။ စကားဝှက်များကို git ပြင်ပတွင် ထားပါ (Android ၏ build စာရွက်စာတမ်း- https://developer.android.com/build/building-cmdline)။
  2. terminal တွင် ./gradlew bundleRelease ကို ပြေးပါ။ Gradle က bundle ကို build လုပ်၍ signing လုပ်ပေးသည်။ .aab သည် ပုံမှန်အားဖြင့် app/build/outputs/bundle/release/ အောက်တွင် ပေါ်လာသော်လည်း သင့်ကိုယ်ပိုင် build output ကို စစ်ပါ။
  3. keystore မရှိလျှင် keytool ဖြင့် တစ်ခုဖန်တီး၍ backup လုပ်ထားပါ။ ပထမဆုံး release ကို upload လုပ်သောအခါ Google Play App Signing ကို ကမ်းလှမ်းလိမ့်မည်။

၂။ Play Console တွင် closed testing စတင်ပါ

  1. Test and release > Testing > Closed testing ကိုဖွင့်ပြီး Create track (သို့မဟုတ် Manage track) ကို နှိပ်ပါ။
  2. Create new release ကိုနှိပ်ပါ၊ .aab ကို upload လုပ်ပါ၊ release အမည်နှင့် မှတ်စုများထည့်ပါ၊ Save as draft၊ Next၊ ထို့နောက် Start rollout (အဆင့်များ- https://support.google.com/googleplay/android-developer/answer/9859348)။
  3. Dashboard ရှိ app တပ်ဆင်မှုလုပ်ငန်းများကို အရင်ပြီးစီးပါ၊ မဟုတ်ပါက release ခလုတ်သည် ပိတ်ထားဆဲဖြစ်လိမ့်မည်။

၃။ tester ၁၂ ဦးကို ရယူပါ- အခမဲ့အရင်၊ ငွေပေးနောက်

  • အခမဲ့လမ်းကြောင်း- သင့်ဖုန်းတွင် https://testerexchange.com/earn ကိုဖွင့်ပြီး သင့်အား ပေးထားသော app များကို စမ်းသပ်ပါ။ သင်စမ်းသပ်သော app တစ်ခုတိုင်းက သင့် app သို့ tester တစ်ဦးကို ယူဆောင်လာသည်။
  • ငွေပေးလမ်းကြောင်း- တစ်ကြိမ်ပေးချေလိုက်လျှင် tester များကို အလိုအလျောက် သတ်မှတ်ပေးသည်။ လက်ရှိစျေးနှုန်းများကို https://testerexchange.com/llms.txt တွင် စာရင်းပြထားသည်။
  • တစ်ဦးထွက်သွားလျှင် Google ၏ အနည်းဆုံးကန့်သတ်ချက်အောက် မကျစေရန် tester ၁၂ ဦးအစား ၁၅ ဦး တောင်းပါ။

၄။ Tester Exchange ကို Cursor နှင့် ချိတ်ဆက်ပါ (ရွေးချယ်စရာ)

ပထမဦးစွာ https://testerexchange.com/api တွင် API key တစ်ခု ဖန်တီးပါ။ ထို့နောက် ၎င်းကို သင့်ပရောဂျက်ရှိ .cursor/mcp.json တွင် ထည့်ပါ၊ သို့မဟုတ် နေရာတိုင်းတွင် သုံးလိုလျှင် ~/.cursor/mcp.json တွင် ထည့်ပါ (ဖိုင်တည်နေရာများကို Cursor ၏ MCP စာရွက်စာတမ်း https://cursor.com/docs/context/mcp မှ ယူထားသည်)။ key ကို commit မလုပ်မိစေရန် သင့် shell ပတ်ဝန်းကျင်တွင် TESTER_EXCHANGE_KEY ကို အရင်သတ်မှတ်ပါ-

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Cursor သည် url နှင့် headers အကွက်များရှိ ${env:NAME} ကို ဖြေရှင်းပေးသည်။ server တစ်ခု မတင်နိုင်ပါက Output panel ကိုဖွင့်ပြီး MCP Logs ကို ရွေးပါ။ server သည် OAuth မပါသော Streamable HTTP အပေါ်ရှိ ရိုးရိုး MCP ဖြစ်သည်။ အများသုံးကိရိယာများ (about၊ pricing၊ platform_stats) သည် key မလိုဘဲ အလုပ်လုပ်သည်။

၅။ agent ကို မေးပါ

  • “Tester Exchange ကိုသုံး၍ com.example.app အတွက် tester ၁၅ ဦးရယူပြီး Play Console တွင် ကျွန်ုပ်ဘာလုပ်ရမည်ကို ပြောပြပါ။”
  • “com.example.app အတွက် ကျွန်ုပ်၏ Tester Exchange campaign ကိုစစ်ပြီး မနေ့က tester ဘယ်နှစ်ဦး လှုပ်ရှားခဲ့သည်ကို ပြောပြပါ။”
  • “campaign report ကိုယူပြီး တကယ့်ကိန်းဂဏန်းများအပေါ် အခြေခံ၍ production ဝင်ရောက်ခွင့် အဖြေများကို မူကြမ်းရေးပေးပါ။”

အဓိကကိရိယာမှာ get_testers ဖြစ်သည်- ၎င်းက app ကိုထည့်ပြီး စမ်းသပ်မှုကိုဖွင့်ကာ Play Console တွင် tester များ၏ Google Group ထည့်ခြင်းကဲ့သို့ လူသာလုပ်နိုင်သော အဆင့်များကို ပြန်ပေးသည်။ agent သည် သင့်အစား ငွေပေးချေခြင်း သို့မဟုတ် Apply for production ကို နှိပ်ခြင်း မလုပ်နိုင်ပါ။

MCP မရှိဘူးလား။ HTTP API ကို သုံးပါ

https://testerexchange.com/agents/ တွင် စာရင်းပြထားသော အများသုံး apikey header နှင့် {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}} body ဖြင့် https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call သို့ POST လုပ်ပါ။ schema သည် https://testerexchange.com/openapi.json တွင် ရှိသည်။ ကိရိယာများ ပိုမိုလိုလျှင်- https://testerexchange.com/guide/ai-builders/ ။

မေးလေ့ရှိသော မေးခွန်းများ

Cursor က ကျွန်ုပ်အစား ၁၄ ရက် စမ်းသပ်မှုကို ပြီးအောင်လုပ်ပေးနိုင်ပါသလား။

မရပါ။ ထို ၁၄ ရက်အတွက် သင့် app ကို ကိုယ်ပိုင် Android ဖုန်းများပေါ်တွင် သုံးမည့် တကယ့်လူများ လိုအပ်သည်။ Cursor က app ကို build လုပ်ပြီး တပ်ဆင်မှုကို မောင်းနှင်ပေးနိုင်သည်။

Tester Exchange သည် Cursor ၏ တရားဝင် ပေါင်းစပ်မှုလား။

မဟုတ်ပါ။ HTTP ပေါ်ရှိ remote MCP ကို ပံ့ပိုးသော client မည်သည့်အရာနှင့်မဆို အလုပ်လုပ်သော လွတ်လပ်သည့် ဝန်ဆောင်မှုဖြစ်ပြီး Cursor သည် ထိုသို့ပံ့ပိုးသည်။

AAB ကို ဘယ်မှာ upload လုပ်ရမလဲ။

Play Console ရှိ closed testing release တစ်ခုသို့ upload လုပ်ပြီး ထို track တွင် သင့် tester များ၏ Google Group သို့မဟုတ် အီးမေးလ်စာရင်းကို ထည့်ပါ။

tester ၁၂ ဦးကို အခမဲ့ရယူရန် နည်းလမ်းရှိပါသလား။

ရှိပါသည်။ https://testerexchange.com/earn တွင် အခြားဒေဗလပ်ပါများ၏ app များကို စမ်းသပ်ပါ။ သင်စမ်းသပ်သော app တစ်ခုတိုင်းက သင့် app သို့ tester တစ်ဦးကို ယူဆောင်လာသည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်

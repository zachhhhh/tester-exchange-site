Tester Exchange Tester Exchange ဖွင့်ရန်

App Inventor၊ Kodular၊ Flutter၊ Unity နှင့် အခြား tool များဖြင့် ဖန်တီးထားသော app များအတွက် Google Play tester ၁၂ ယောက်

2026 အောက်တိုဘာတွင် update လုပ်ထားသည်

သင့် app ကို ဘယ် tool နဲ့ တည်ဆောက်ခဲ့သလဲဆိုတာ အရေးမကြီးပါ။ သင့် Google Play developer account သည် personal account အသစ်ဖြစ်လျှင် production သို့ publish မလုပ်မီ အနည်းဆုံး tester ၁၂ ယောက်ပါသော ၁၄ ရက် closed test လိုအပ်သည်။ ဤလမ်းညွှန်သည် app builder tool များနှင့် game engine များ သုံးသူများ အများဆုံး အခက်တွေ့သော အချက်များနှင့် tester များကို အခမဲ့ ရှာနိုင်သော နည်းလမ်းကို ရှင်းပြပေးသည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်
ဤစာမျက်နှာတွင်
  • စည်းမျဉ်းသည် tool တိုင်းအတွက် အတူတူပင်
  • အဆင့် ၁: သင့် tool က sign လုပ်နိုင်သော release build ကို export လုပ်ပါ
  • အဆင့် ၂: closed test ကို setup လုပ်ပါ
  • အဆင့် ၃: ၁၄ ရက် ဆက်ရှိနေမည့် tester ၁၂ ယောက်ကို ရှာပါ
  • အဆင့် ၄: tester များကို active ဖြစ်နေစေပြီး update ထုတ်ပါ
  • အဆင့် ၅: production လျှောက်ပါ
  • မကြာခဏ မေးလေ့ရှိသော မေးခွန်းများ

စည်းမျဉ်းသည် tool တိုင်းအတွက် အတူတူပင်

Google သည် သင့် tool ကို မဟုတ်ဘဲ သင့် developer account ကို စစ်ဆေးသည်။ MIT App Inventor၊ Kodular၊ Niotron၊ Sketchware၊ Thunkable၊ FlutterFlow၊ Flutter၊ React Native၊ Expo၊ Unity သို့မဟုတ် Godot ဖြင့် ဖန်တီးထားသော app အားလုံး တူညီသော closed test ကို ဖြတ်သန်းရသည်။

သင်သည် personal developer account ကို 2023 နိုဝင်ဘာ 13 ရက်နောက်ပိုင်း ဖွင့်ခဲ့လျှင် production access မလျှောက်မီ အနည်းဆုံး tester ၁၂ ယောက်က ၁၄ ရက် ဆက်တိုက် opt in လုပ်ထားရန် လိုအပ်သည်။ Organization account များတွင် ဤလိုအပ်ချက် မရှိပါ။

အဆင့် ၁: သင့် tool က sign လုပ်နိုင်သော release build ကို export လုပ်ပါ

  1. Android App Bundle (.aab) ကို export လုပ်ပါ။ Google Play သည် app အသစ်များအတွက် .aab ကို လိုအပ်သည်။ Tool နှင့် engine အများစုက export လုပ်ပေးနိုင်သည်; သင့် tool က APK ကိုသာ ပေးလျှင် ၎င်း၏ documentation တွင် App Bundle option ကို ရှာကြည့်ပါ။
  2. သင့် signing key ကို လုံခြုံစွာ သိမ်းထားပါ။ App Inventor နှင့် Kodular ကဲ့သို့သော tool များက သင့်အတွက် keystore ကို ဖန်တီးပေးသည်။ ၎င်း၏ backup ကို download လုပ်ထားပါ။ Update တိုင်းအတွက် တူညီသော key လိုအပ်သည်။
  3. Package name ကို သေချာ ရွေးပါ။ App သည် Google Play ပေါ် ရောက်ပြီးနောက် ၎င်းကို ဘယ်တော့မှ ပြောင်း၍ မရပါ။
  4. Target API level ကို ပြည့်မီပါစေ။ Google Play သည် မကြာသေးမီ Android version ကို target ထားသော build များကိုသာ လက်ခံသည်။ Target API level ကြောင့် upload ငြင်းပယ်ခံရလျှင် သင့် tool သို့မဟုတ် engine ကို update လုပ်ပြီး ပြန် export လုပ်ပါ။

အဆင့် ၂: closed test ကို setup လုပ်ပါ

  1. Play Console တွင် Test and release → Testing → Closed testing ကို ဖွင့်ပြီး track တစ်ခု ဖန်တီးပါ။
  2. Tester များကို email list အစား Google Group ဖြင့် ထည့်ပါ: tester များက group တွင် ကိုယ်တိုင် ဝင်ကြပြီး သင် email များကို ထပ်မံ paste လုပ်စရာ မလိုတော့ပါ။
  3. သင့် .aab ကို closed track သို့ upload လုပ်ပြီး release notes ထည့်ကာ review အတွက် ပို့ပါ။
  4. Opt-in link ကို copy ကူးပါ။ Tester များက group တွင် ဝင်ပြီး opt-in link ကို ဖွင့်ကာ "Become a tester" ကို နှိပ်ပြီးနောက် Google Play မှ install လုပ်ကြသည်။

အဆင့် ၃: ၁၄ ရက် ဆက်ရှိနေမည့် tester ၁၂ ယောက်ကို ရှာပါ

စာရင်းပေါ်ရှိ နာမည် ၁၂ ခုက မလုံလောက်ပါ။ Tester များ သင့် app ကို တကယ်သုံးခဲ့သလားဆိုတာကို Google က စစ်ဆေးပြီး ၁၄ ရက်သည် အနည်းဆုံး tester ၁၂ ယောက် opt in လုပ်ထားချိန်တွင်သာ ရေတွက်သည်။ တစ်ယောက်နှစ်ယောက် ထွက်သွားလည်း ရေတွက်မှု မရပ်သွားအောင် ၁၄ သို့မဟုတ် ၁၅ ယောက် ခေါ်ပါ။

  • Android ဖုန်းရှိသော မိတ်ဆွေများနှင့် မိသားစု: အခမဲ့ဖြစ်သော်လည်း ရက်အနည်းငယ်အကြာတွင် app ကို မဖွင့်တော့တာ မကြာခဏ ဖြစ်တတ်သည်။
  • Tool community များနှင့် forum များ: တူညီသော tool သုံးသူများက စည်းမျဉ်းကို နားလည်ပြီး အများအပြားက test များ လဲလှယ်ကြသည်။
  • Test လဲလှယ်ရေး: Tester Exchange တွင် သင့်ဖုန်းသို့ စမ်းသပ်ရန် အခြား developer များ၏ app များ ပေးမည်၊ တစ်ရက် တစ်မိနစ်၊ သင်စမ်းသပ်သော app တစ်ခုစီက သင့် app သို့ tester တစ်ယောက် ခေါ်လာသည်။

အဆင့် ၄: tester များကို active ဖြစ်နေစေပြီး update ထုတ်ပါ

  • App ကို ဖွင့်စရာ အကြောင်းရှိအောင် tester များကို နေ့စဉ် အလုပ်သေးသေး တစ်ခု ပေးပါ။
  • ၇ ရက်မြောက်နေ့ ဝန်းကျင်တွင် fix များပါသော build အသစ်ကို upload လုပ်ပြီး ဘာပြောင်းသွားသလဲ ပြောပါ။ ဤ tool များဖြင့် မြန်ဆန်သည်: export လုပ်၊ တူညီသော closed track သို့ upload လုပ်၊ ပြီးပါပြီ။
  • စာဖြင့် feedback တောင်းပြီး ပြင်နိုင်သမျှ ပြင်ပါ။ ၎င်းက production မေးခွန်းများအတွက် တကယ့်အဖြေများကိုလည်း ပေးသည်။

အဆင့် ၅: production လျှောက်ပါ

၁၄ ရက်အပြီး Play Console dashboard တွင် production access လျှောက်ပါ။ Google က tester များကို ဘယ်လို ရှာခဲ့သလဲ၊ သူတို့ app ကို ဘယ်လို သုံးခဲ့သလဲနှင့် သူတို့၏ feedback အပေါ် အခြေခံ၍ ဘာတွေ ပြောင်းခဲ့သလဲ မေးသည်။ သင့် test မှ တကယ့်ဂဏန်းများဖြင့် ဖြေပါ။ Google သည် များသောအားဖြင့် တစ်ပတ်ခန့်အတွင်း ပြန်ကြားသည်။

မကြာခဏ မေးလေ့ရှိသော မေးခွန်းများ

App Inventor သို့မဟုတ် Kodular ဖြင့် ဖန်တီးထားသော app များလည်း tester ၁၂ ယောက် လိုသလား?

လိုပါသည်။ လိုအပ်ချက်သည် tool ပေါ်တွင် မဟုတ်ဘဲ သင့် developer account ပေါ်တွင် မူတည်သည်။ App ကို ဘာနဲ့ တည်ဆောက်ခဲ့သည်ဖြစ်စေ personal account အသစ်များသည် ၁၄ ရက် opt in လုပ်ထားသော tester ၁၂ ယောက် လိုအပ်သည်။

ကျွန်ုပ်၏ tester များက ကျွန်ုပ်ပို့ပေးသော APK ကို အစားထိုး install လုပ်လို့ရသလား?

မရပါ။ Google Play ပေါ်ရှိ closed test မှ install များကိုသာ ရေတွက်သည်။ Tester များသည် Play Console မှ link ဖြင့် opt in လုပ်ပြီး Play Store မှ install လုပ်ရမည်။

Closed test စတင်ရန် build အသစ် လိုသလား?

Closed track သို့ upload လုပ်ထားသော build အနည်းဆုံး တစ်ခု လိုအပ်သည်။ Test အတွင်း tester feedback မှ fix များပါသော ဒုတိယ build ကို upload လုပ်ခြင်းက ကောင်းသော အကြံဖြစ်သည်။

Tester ၁၂ ယောက်ကို အခမဲ့ ရနိုင်သော နည်းလမ်း ရှိသလား?

ရှိပါသည်။ Test လဲလှယ်ခြင်းများသည် အခမဲ့ဖြစ်သည်: သင်က အခြား developer များ၏ app များကို စမ်းသပ်ပြီး သူတို့က သင့် app ကို စမ်းသပ်ကြသည်။ Tester Exchange သည် tester တစ်ယောက်စီ၏ ဖုန်းပေါ်တွင် နေ့စဉ်အသုံးပြုမှုကို အတည်ပြုသဖြင့် testing သည် တကယ်ဖြစ်သည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်

  • Google Play closed testing အတွက် tester ၁၂ ယောက်ကို အခမဲ့ ရယူနည်း
  • မိတ်ဆွေများနှင့် မိသားစုကို သင့် Google Play tester ၁၂ ယောက်အဖြစ် အသုံးပြုခြင်း

AI agent များဖြင့် Google Play closed testing ကို automate လုပ်ပါ

2026 နိုဝင်ဘာတွင် update လုပ်ထားသည်

AI agent တစ်ခုနှင့် code ကို ship လုပ်နေပြီးသားဆိုလျှင် Google Play ၏ closed testing လိုအပ်ချက်ဆိုင်ရာ အလုပ်ကြမ်းအများစုကိုလည်း ၎င်းကို လွှဲပေးနိုင်သည်: app စာရင်းသွင်းခြင်း၊ tester ရှာခြင်း၊ တိုးတက်မှု စစ်ခြင်းနှင့် production access form အတွက် ကိန်းဂဏန်းများ ထုတ်ယူခြင်း။ Tester Exchange တွင် ဤအတွက် MCP server၊ endpoint တစ်ခုတည်းပါ HTTP API နှင့် A2A agent card ရှိသည်။ ဤလမ်းညွှန်တွင် Claude Code၊ Claude Desktop၊ Cursor နှင့် အခြား client များကို ချိတ်ဆက်နည်း၊ ဘာတွေ တောင်းဆိုရမည်၊ agent မည်သူမျှ သင့်အတွက် မလုပ်နိုင်သော အပိုင်းများကို ပြသထားသည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်

Agent တစ်ခု ဘာလုပ်နိုင်၊ ဘာမလုပ်နိုင်လဲ

2023 နိုဝင်ဘာ ၁၃ ရက်နောက်ပိုင်း ဖွင့်ထားသော personal developer account များသည် production လျှောက်မီ tester အနည်းဆုံး ၁၂ ယောက်ကို ၁၄ ရက် ဆက်တိုက် opt in လုပ်ထားသော closed test လုပ်ရန် Google က လိုအပ်သည်။ ယင်းနှင့်ပတ်သက်သော အလုပ်အများစုမှာ ညှိနှိုင်းဆောင်ရွက်ခြင်းဖြစ်ပြီး agent များက ကောင်းစွာ လုပ်နိုင်သည်။

  • Agent လုပ်နိုင်သည်: သင့် app ကိုထည့်ခြင်း၊ tester campaign ဖွင့်ခြင်း၊ သင့် credit များကို သုံးခြင်း၊ tester မည်မျှ တက်ကြွနေသည်ကို စစ်ခြင်း၊ campaign ကို pause သို့မဟုတ် ပိတ်ခြင်း၊ နေ့စဉ်လှုပ်ရှားမှု report ကို ယူခြင်းနှင့် ၎င်းမှ production access အဖြေများကို ရေးကူခြင်း။
  • လူက လုပ်ရမည်: Play Console ရှိ closed track တွင် tester များ၏ Google Group ကို ထည့်ခြင်း၊ release ကို publish လုပ်ခြင်း၊ credit အတွက် ငွေပေးချေခြင်း (checkout ကို လူ၏ browser ထဲတွင်သာ လုပ်သည်) နှင့် Apply for production ကို နှိပ်ခြင်း။
  • မည်သူမျှ automate မလုပ်နိုင်သည်: တကယ့်အသုံးပြုမှု ၁၄ ရက်။ ၎င်းကို လူအစစ်များက ကိုယ်ပိုင် Android ဖုန်းများပေါ်တွင် လုပ်ပေးသည်၊ ထိုအချက်ကပင် Google ၏ စည်းမျဉ်း၏ ရည်ရွယ်ချက်ဖြစ်သည်။

၁။ Token တစ်ခု ဖန်တီးပါ

  1. https://testerexchange.com/api တွင် sign in ဝင်ပါ။
  2. Personal token တစ်ခု ဖန်တီးပါ။ ၎င်းသည် tx_ ဖြင့် စသည်။ ယခုပင် copy ကူးပြီး password ကဲ့သို့ သိမ်းထားပါ။
  3. Token များကို မည်သည့်အချိန်တွင်မဆို revoke လုပ်နိုင်သည်။ Token တစ်ခုက campaign များအတွက် credit သုံးနိုင်သော်လည်း ငွေပေးချေ၊ ငွေထုတ် သို့မဟုတ် သင့် account ကို ဖျက်၍ မရပါ။

၂။ MCP server ကို ချိတ်ဆက်ပါ

MCP server သည် https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp တွင် Streamable HTTP ကို သုံးသည်။ သင့် token ကို header တွင် Authorization: Bearer tx_YOUR_TOKEN ဟု ပို့ပါ။

Claude Code: သင့် terminal တွင် ဤ command ကို တစ်ကြိမ်ရိုက်ပါ။

claude mcp add --transport http tester-exchange https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp --header "Authorization: Bearer tx_YOUR_TOKEN"

Claude Desktop၊ Cursor၊ VS Code နှင့် JSON config သုံးသော အခြား client များ: tester-exchange အမည်ရှိ server တစ်ခုကို type http၊ အထက်ပါ URL နှင့် Authorization ကို Bearer tx_YOUR_TOKEN ဟု သတ်မှတ်ထားသော headers entry တစ်ခုဖြင့် ထည့်ပါ။ Config ဖိုင်၏ တည်နေရာသည် သင့် client ပေါ်မူတည်သည်၊ ၎င်း၏ MCP documentation ကို ကြည့်ပါ။

URL တစ်ခုသာ လက်ခံသော client များ (ChatGPT နှင့် web connector အချို့): https://testerexchange.com/agents/ ရှိ docs တွင် ၎င်းတို့အတွက် URL ပုံစံ ဖော်ပြထားသည်။ Token မပါလျှင်လည်း public tool များ (Tester Exchange ဆိုတာ ဘာလဲ၊ စျေးနှုန်း၊ platform စာရင်းအင်း) ဆက်အလုပ်လုပ်သည်။

၃။ စတင်ရန် tool တစ်ခု: get_testers

Tool စာရင်းတစ်ခုလုံးကို လေ့လာစရာ မလိုပါ။ အဓိက tool မှာ get_testers(package_name, name?) ဖြစ်သည်။ ခေါ်ဆိုမှုတစ်ခုတည်းဖြင့် သင့် app ကို ထည့်ပြီး test ကိုဖွင့်ကာ သင့် credit များကို သုံးပြီး သင့်တိုးတက်မှုနှင့်အတူ Play Console တွင် Google Group ထည့်ခြင်းကဲ့သို့ လူကသာ လုပ်နိုင်သော အဆင့်များကို ပြန်ပေးသည်။ တိုးတက်မှု စစ်ရန် မည်သည့်အချိန်တွင်မဆို ထပ်ခေါ်နိုင်သည်။

အခြား tool များက အသေးစိတ်ကို ဖုံးအုပ်ထားသည်: my_apps၊ campaign_report (tester များ၊ နေ့စဉ်လှုပ်ရှားမှု၊ feedback နှင့် production-access ဒေတာ)၊ add_testers၊ set_campaign_status (pause၊ resume သို့မဟုတ် ပိတ်ခြင်း၊ မသုံးရသေးသော credit များ သင့်လက်ကျန်သို့ ပြန်ရောက်သည်)၊ share_kit နှင့် လူက ငွေပေးချေရန် checkout link များ ပြန်ပေးသော buy_credits_links။

ထိရောက်သော prompt များ

  • "com.example.app အတွက် tester ၁၅ ယောက် ရယူပေးပြီး Play Console တွင် ကျွန်ုပ် ဘာလုပ်ရမလဲ ပြောပါ။"
  • "com.example.app အတွက် ကျွန်ုပ်၏ Tester Exchange campaign ကို စစ်ပါ။ ဤအပတ်တွင် နေ့တိုင်း tester ဘယ်နှစ်ယောက် တက်ကြွခဲ့သလဲ?"
  • "Campaign report ကို ထုတ်ပြီး ကျွန်ုပ်၏ production access အဖြေများကို ရေးကူပါ။ တကယ့်ကိန်းဂဏန်းများကိုသာ သုံးပါ။"
  • "Production access ခွင့်ပြုပြီးပြီဖြစ်သောကြောင့် com.example.app အတွက် campaign ကို ယခု ပိတ်ပါ။"

၁၂ ယောက်အစား ၁၅ ယောက်ကို တောင်းပါ၊ ထိုအခါ ထွက်သွားသူတစ်ယောက်ကြောင့် Google ၏ အနည်းဆုံးအောက် မရောက်တော့ပါ။

Script များနှင့် CI အတွက် HTTP API

သင့် tool က MCP ကို မသုံးလျှင် HTTP endpoint ကို သုံးပါ: POST https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call။ Body သည် JSON ဖြစ်ပြီး p_token (သင့် tx_ token)၊ p_action (ဥပမာ help၊ my_apps သို့မဟုတ် start_campaign) နှင့် p_args (ဥပမာ package_name နှင့် tester အရေအတွက်) ပါသည်။ Docs တွင် ပြထားသော public apikey header ကိုလည်း ပို့ပါ။

ပထမဦးစွာ help action ကို ခေါ်ပါ: ၎င်းက action အားလုံးနှင့် ၎င်းတို့၏ argument များကို ပြန်ပေးသည်။ Schema အပြည့်အစုံသည် https://testerexchange.com/openapi.json တွင် ရှိပြီး ChatGPT custom GPT action များနှင့် အခြား OpenAPI tool များနှင့် အလုပ်လုပ်သည်။

A2A agent card

Agent အချင်းချင်း setup များအတွက် Tester Exchange သည် https://testerexchange.com/.well-known/agent-card.json တွင် A2A agent card ကို ထုတ်ပြန်ထားသည်။ A2A protocol ကို ပံ့ပိုးသော orchestrator များက agent ၏ ပေးစွမ်းနိုင်သည့်အရာများနှင့် ခေါ်ဆိုပုံကို ရှာဖွေတွေ့ရှိနိုင်သည်။ သင့် account နှင့်ဆိုင်သော မည်သည့်အရာအတွက်မဆို တူညီသော tx_ token ကို သုံးပါ။

အစမှ အဆုံးထိ အပြည့်အစုံ run တစ်ခု

  1. Play Console ရှိ closed track သို့ သင်၏ ပထမဆုံး .aab ကို upload လုပ်ပါ။
  2. သင့် agent က သင့် package name အတွက် get_testers ကိုခေါ်ပြီး closed track ၏ Google Groups အောက်တွင် testerexchange-testers@googlegroups.com ကို ထည့်ရန် ပြောပြသည်။
  3. Group ကိုထည့်ပြီး သိမ်းကာ release ကို publish လုပ်ထားကြောင်း သေချာစေပါ။
  4. Credit မလုံလောက်လျှင် agent က checkout link တစ်ခု ပေးသည်။ သင်ပေးချေပါ ($12.99 က tester ၁၂ ယောက်၊ $14.99 က ၁၅ ယောက်၊ $22.99 က ၂၅ ယောက်)၊ သို့မဟုတ် https://testerexchange.com/earn တွင် အခြား app များကို စမ်းသပ်ပြီး credit ကို အခမဲ့ ရယူပါ။
  5. တကယ့် tester များက သင့် app ကို ၁၄ ရက် install လုပ်ပြီး အသုံးပြုသည်။ သင့် agent က နေ့စဉ် တိုးတက်မှုကို စစ်ပြီး တက်ကြွသော tester များ ကျဆင်းလျှင် သတိပေးသည်။
  6. ၁၅ ရက်မြောက်နေ့တွင် agent က campaign report ကို ထုတ်ယူပြီး သင့် production access အဖြေများကို ရေးကူပေးသည်။ သင်က ပြန်ကြည့်ပြီး Apply for production ကို နှိပ်ပါ။

လုံခြုံရေး မှတ်ချက်များ

  • Token များကို git ထဲ မထည့်ပါနှင့်။ သင့် client ၏ secret store သို့မဟုတ် environment variable တွင် ထားပါ။
  • ကျွန်ုပ်တို့ဘက်တွင် token များကို hash အဖြစ်သာ သိမ်းဆည်းပြီး account တစ်ခုလျှင် ၁၀ ခုအထိသာ ခွင့်ပြုသည်။ မသုံးတော့သော token ကို revoke လုပ်ပါ။
  • သင်မတင်သွင်းမီ production form တွင် agent ရေးထားသည်ကို ဖတ်ပါ။ Google က သင့် test ကို ရိုးသားစွာ ဖော်ပြရန် တောင်းဆိုသည်။

မလုပ်နိုင်ပါ။ ၁၄ ရက်အတွက် လူအစစ်များက ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် သင့် app ကို သုံးရမည်။ Agent များက setup၊ စောင့်ကြည့်ခြင်းနှင့် report ပြုစုခြင်းကို ကိုင်တွယ်သည်။

Agent က tester များအတွက် ငွေပေးချေနိုင်သလား?

မပေးချေနိုင်ပါ။ Checkout link များ ပြန်ပေးနိုင်သော်လည်း ငွေပေးချေမှုကို လူ၏ browser တွင်သာ လုပ်သည်။

MCP server နှင့် မည်သည့် client များ အလုပ်လုပ်သလဲ?

Custom header ပါသော Streamable HTTP ဖြင့် remote MCP ကို ပံ့ပိုးသည့် client မည်သည့်အရာမဆို၊ Claude Code၊ Claude Desktop၊ Cursor နှင့် VS Code အပါအဝင်။ အခြားများက HTTP API ကို သုံးနိုင်သည်။

Token ကို ဘယ်မှာ ရနိုင်သလဲ?

Sign in ဝင်ပြီးနောက် https://testerexchange.com/api တွင်။ Token များသည် tx_ ဖြင့် စပြီး မည်သည့်အချိန်တွင်မဆို revoke လုပ်နိုင်သည်။

Agent က ကျွန်ုပ်၏ Play Console တွင် ဘာမှ ပြောင်းလဲသလား?

မပြောင်းပါ။ ၎င်းတွင် သင့် Play Console သို့ ဝင်ခွင့် မရှိပါ။ ထိုနေရာတွင် လုပ်ရမည့်အဆင့်များကို ပြောပြသည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်

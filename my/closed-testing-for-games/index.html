Google Play ပေါ်ရှိ game များအတွက် closed testing: Unity, Unreal နှင့် Godot လမ်းညွှန်

2026 နိုဝင်ဘာတွင် update လုပ်ထားသည်

Game များသည် အခြား app များကဲ့သို့ပင် တူညီသော closed testing လိုအပ်ချက်ကို ဖြတ်သန်းရသည်: သင့် personal developer account ကို 2023 နိုဝင်ဘာ ၁၃ ရက်နောက်ပိုင်း ဖွင့်ခဲ့လျှင် production လျှောက်မီ tester အနည်းဆုံး ၁၂ ယောက်ကို ၁၄ ရက်ဆက်တိုက် opt in လုပ်ထားရမည်။ သို့သော် game များတွင် ကိုယ်ပိုင် အခက်အခဲများ ရှိသည်: download အကြီးကြီးများ၊ build ကို မ run နိုင်သော device များနှင့် game ကို တစ်ကြိမ်ဖွင့်ပြီး ပြန်မလာတော့သော tester များ။ ဤလမ်းညွှန်တွင် game developer များ ဘာတွေ setup လုပ်သင့်သလဲ၊ tester များကို ဘာလုပ်ခိုင်းသင့်သလဲ ဖော်ပြထားသည်။

တကယ့်လူများက သင့် app ကို ကိုယ်ပိုင်ဖုန်းများပေါ်တွင် ၁၄ ရက် ဖွင့်ကြသည်။ တစ်ကြိမ် ပေးချေပါ၊ သို့မဟုတ် အခြား app များကို အခမဲ့ စမ်းသပ်ပါ။Tester ၁၂ ယောက် ရယူရန်

စည်းမျဉ်းတူ၊ ဒါပေမယ့် game အတွက် သီးသန့်အန္တရာယ်များ

Google သည် ဤနေရာတွင် game နှင့် app ကို တူညီစွာ ဆက်ဆံသည်။ Tester အနည်းဆုံး ၁၂ ယောက်ကို ၁၄ ရက်ဆက်တိုက် opt in ထားစေသော closed test တစ်ခု လုပ်ပြီးမှ production သို့ လျှောက်ပါ။ Production form က tester engagement၊ feedback နှင့် သင်ပြောင်းလဲခဲ့သည်များကို မေးသောကြောင့် tutorial ကျော်ပြီး ဘယ်သူမျှ မကစားခဲ့သော test သည် အဖြေများ အားနည်းစေသည်။

အခြား app များထက် game များကို ပိုထိခိုက်သော အန္တရာယ်များ:

  • Device compatibility: Tester များက "your device isn't compatible" ဟု မြင်ပြီး install မလုပ်နိုင်ပါ။
  • Download အရွယ်အစား: mobile data ဖြင့် ပထမဆုံး download ကြီးမားလျှင် tester များ စိတ်ပျက်သွားသည်။
  • Session ကြာချိန်: နှစ်ပတ်တိုင်တိုင် နေ့တိုင်း မိနစ် ၂၀ ကြာသော level ကို ဘယ်သူမျှ မကစားပါ။
  • Content ကွာဟချက်: level တစ်ခုတည်းပါသော vertical slice ဖြင့် တတိယနေ့လောက်တွင် လုပ်စရာ ကုန်သွားသည်။

ပထမဦးဆုံး စစ်ရန် build setting များ

  • Unity: Android App Bundle (.aab) ကို build လုပ်ပါ၊ ARM64 ဖွင့်ထားသော IL2CPP ကို သုံးပါ (Google Play က 64-bit ပံ့ပိုးမှု လိုအပ်သည်)၊ ပြီးလျှင် လိုအပ်သည်ထက် ဖုန်းများစွာကို မဖယ်ထုတ်သော minimum API level ကို သတ်မှတ်ပါ။ Build ကြီးလျှင် download ကြီးတစ်ခုအစား Play Asset Delivery ကို သုံးပါ။
  • Unreal Engine: arm64 ပါသော App Bundle အဖြစ် Android အတွက် package လုပ်ပါ၊ Project Settings ရှိ target နှင့် minimum SDK level များကို စစ်ပါ၊ ရွေးချယ်နိုင်သော content ကို asset pack များသို့ ရွှေ့ပြီး ပထမ download ကို သေးအောင်ထားပါ။
  • Godot: Gradle build ဖွင့်ထားသော Android export template ကို သုံးပြီး AAB အဖြစ် export လုပ်ပါ။ arm64-v8a ပါဝင်ကြောင်း သေချာစေပြီး low-end ဖုန်းတစ်လုံးပေါ်တွင် renderer ကို စမ်းပါ၊ အဘယ်ကြောင့်ဆိုသော် device အချို့သည် Forward+ သို့မဟုတ် Mobile ထက် Compatibility renderer ကို ပိုကောင်းစွာ ကိုင်တွယ်နိုင်သည်။
  • Engine အားလုံး: Google Play က အက်ပ်အသစ်များအတွက် လက်ရှိ လိုအပ်သော API level ကို target လုပ်ပြီး Play App Signing ဖြင့် sign လုပ်ပါ။

Upload လုပ်ပြီးနောက် သင့် build က device မည်မျှကို ပံ့ပိုးသည်ကို ကြည့်ရန် Play Console ရှိ Device catalog ကိုဖွင့်ပါ။ အပုံကြီးကို ဖယ်ထုတ်ထားလျှင် tester များ မရောက်မီ ပြင်ပါ။

Test ကို setup လုပ်ပါ

  1. Closed track ကို ဖန်တီးပါ သို့မဟုတ် ဖွင့်ပါ: Test and release → Testing → Closed testing။
  2. သင့် tester များ နေထိုင်ရာ နိုင်ငံများကို ထည့်ပါ။
  3. Email list သို့မဟုတ် Google Group ဖြင့် tester များကို ထည့်ပါ။ Tester Exchange ဖြင့်ဆိုလျှင် testerexchange-testers@googlegroups.com ကို ထည့်ပါ။
  4. .aab ကို upload လုပ်ပြီး release ကို review သို့ ပို့ကာ Published ပြသည်အထိ စောင့်ပါ။
  5. Opt-in link ကို မျှဝေပါ။ ပထမအကြိမ်တွင် အလုပ်လုပ်စတင်ရန် နာရီများစွာ ကြာနိုင်သည်။

Tester များက "app not available" ဟု ပြောလျှင် ၎င်းကို ပြင်ဆင်ရန် လမ်းညွှန်ကို ကြည့်ပါ။ Account မှားခြင်း၊ နိုင်ငံနှင့် မ publish ရသေးသော track များကို ဖုံးအုပ်ထားသည်။

Tester များကို ဘာကစားခိုင်းမလဲ

Tester များကို မိနစ်အနည်းငယ်အတွင်း ပြီးနိုင်သော သေးငယ်သည့် နေ့စဉ်ပန်းတိုင်များ ပေးပါ။ တကယ့်၊ ကွဲပြားသော ကစားမှုက သင့်ကို အကူအညီဖြစ်စေပြီး နောက်ပိုင်း production form တွင် သင်ဖော်ပြမည့်အရာလည်း ဖြစ်သည်။

  • ရက် ၁ မှ ၃: tutorial နှင့် ပထမ level ကို ပြီးအောင်လုပ်ပါ။ ရှုပ်ထွေးသည့်အရာများကို သတင်းပို့ပါ။
  • ရက် ၄ မှ ၇: တစ်နေ့လျှင် session တိုတစ်ခု ကစားပါ၊ setting များ၊ အသံ၊ controls နှင့် pause လုပ်ခြင်းတို့ကို စမ်းကြည့်ပါ။
  • ရက် ၈ မှ ၁၁: ပြင်ဆင်ပြီး build အသစ်ကို စမ်းပါ၊ level တစ်ခုကို ပြန်ကစားပြီး ပိုကောင်းလာမလာ ကြည့်ပါ။
  • ရက် ၁၂ မှ ၁၄: ရရှိနိုင်သမျှ အခက်ခဲဆုံး content ကို ကစားပြီး crash၊ lag သို့မဟုတ် battery ကုန်မှုကို သတင်းပို့ပါ။

သင့် game တွင် နေ့စဉ်ဆုလာဘ်၊ နေ့စဉ်စိန်ခေါ်မှုတိုတစ်ခု သို့မဟုတ် mode မြန်တစ်ခု ရှိလျှင် tester များကို ထိုနေရာသို့ ညွှန်ပါ။ နေ့စဉ်စည်းချက်နှင့် သဘာဝကျစွာ ကိုက်ညီသည်။

Engagement ကို ပြသပါ

  • Test အတွင်း update အနည်းဆုံးတစ်ခု ship လုပ်ပါ၊ နှစ်ခုဆိုလျှင် ပိုကောင်းသည်။ သတင်းပို့ထားသော crash တစ်ခုကို ပြင်ခြင်းသည် production form အတွက် အကောင်းဆုံး ဇာတ်လမ်းဖြစ်သည်။
  • တကယ့် device များပေါ်ရှိ crash နှင့် ANR များကို ရှာရန် Play Console ရှိ Android vitals နှင့် pre-launch report ကို သုံးပါ။
  • Device model၊ သူတို့ ဘာလုပ်ခဲ့သည်၊ ဘာဖြစ်ခဲ့သည်ဟူသော ရိုးရှင်းသည့် form တစ်ခုဖြင့် ရေးသားထားသော feedback ကို စုဆောင်းပါ။
  • နေ့စဉ်တက်ကြွသော tester များ၊ session များ၊ တွေ့ရှိသော bug များနှင့် ship လုပ်ခဲ့သော build များကို မှတ်တမ်းတင်ထားပါ။

Multiplayer နှင့် online game များ

သင့် game တွင် server လိုအပ်လျှင် ၁၄ ရက်လုံးလုံး ဆက်လည်ပတ်စေပြီး tester များ တစ်ယောက်တည်းရှိနေချိန်တွင်လည်း game ကို ကစားနိုင်ကြောင်း သေချာစေပါ။ ဘယ်တော့မှ မပြည့်သော lobby သည် ဗလာ test တစ်ခုလို ထင်ရသည်။ ဖြစ်နိုင်လျှင် test ကာလအတွက် bot များ သို့မဟုတ် solo mode ထည့်ပါ။

Sign-in လိုအပ်လျှင် tester များကို အလုပ်လုပ်သော guest mode တစ်ခု သို့မဟုတ် ရှင်းလင်းသော ညွှန်ကြားချက်များ ပေးပါ။ Sign-in တံခါးများက ပထမနေ့တွင်ပင် tester များကို ဆုံးရှုံးစေသည်။

ကစားသမား လုံလောက်စွာ ရယူခြင်း

၁၂ ယောက်အစား ၁၅ ယောက်ကို တောင်းပါ၊ အဘယ်ကြောင့်ဆိုသော် ကစားသမားအချို့ game မှ အမြန်ထွက်သွားတတ်သောကြောင့်ဖြစ်သည်။ Tester Exchange က ကိုယ်ပိုင် Android ဖုန်းများပေါ်တွင် ကစားပေးသော လူအစစ်များကို ပို့ပေးပြီး tester တစ်ယောက်စီ၏ နေ့စဉ်အသုံးပြုမှုကို ပြသသည်: ၁၂ ယောက်ကို $12.99၊ ၁၅ ယောက်ကို $14.99 သို့မဟုတ် ၂၅ ယောက်ကို $22.99၊ တစ်ကြိမ်သာ ပေးရသည်။ https://testerexchange.com/earn တွင် အခြား developer များ၏ app နှင့် game များကို စမ်းသပ်ပြီး tester များကို အခမဲ့လည်း ရယူနိုင်သည်။

မကြာခဏ မေးလေ့ရှိသော မေးခွန်းများ

Game များလည်း closed testing လိုအပ်သလား?

လိုအပ်သည်။ ဤလိုအပ်ချက်သည် 2023 နိုဝင်ဘာ ၁၃ ရက်နောက်ပိုင်း ဖွင့်ထားသော personal account များမှ app အားလုံးကို သက်ရောက်ပြီး game များလည်း ပါဝင်သည်။

Closed testing အတွင်း ကျွန်ုပ်၏ game မပြီးသေးဘဲ ရှိနိုင်သလား?

ရှိနိုင်သည်၊ closed test သည် ဆက်လက်ပြုလုပ်နေသော လုပ်ငန်းအတွက်ဖြစ်သည်။ သို့သော် tester များအတွက် နှစ်ပတ်ကစားနိုင်လောက်သော content လိုအပ်ပြီး test အတွင်း ဆက်လက်တိုးတက်အောင် လုပ်သင့်သည်။

Tester အချို့က ကျွန်ုပ်၏ game ကို ဘာကြောင့် install မလုပ်နိုင်ရတာလဲ?

များသောအားဖြင့် device compatibility ကြောင့်ဖြစ်သည်: မြင့်သော minimum Android version၊ 64-bit ပံ့ပိုးမှု မရှိခြင်း သို့မဟုတ် လိုအပ်သော hardware feature များ။ Play Console ရှိ Device catalog ကို စစ်ပါ။

Google က အရေအတွက် မသတ်မှတ်ပါ။ နေ့တိုင်း တကယ့် session တိုတစ်ခုက တစ်ကြိမ်ကြာကြာကစားပြီး နောက်ဘာမှမလုပ်တာထက် ပိုကောင်းသည်။

Test အတွက် Play Asset Delivery ကို သုံးသင့်သလား?

သင့် game ကြီးလျှင် သုံးသင့်သည်။ ပထမ download သေးလေ တကယ် install လုပ်ပြီး ကစားစတင်သော tester များ ပိုများလေဖြစ်သည်။

用 Cursor 开发了 Android 应用？获取 14 天的 12 名测试员

2026 年 11 月更新

Cursor 可以编写并构建你的 Android 应用，但无法提供 Google Play 要求的 12 名真实测试员。如果你的个人开发者账号创建于 2023 年 11 月 13 日之后，就必须先进行封闭测试，且至少有 12 名测试员连续加入 14 天，之后才能申请正式版。本指南涵盖构建应用包、开启封闭测试、获得测试员（先免费，后付费），以及将 Tester Exchange 连接到 Cursor，让代理处理繁琐事务。

1. 构建发布包 (.aab)

  1. 让 Cursor 的代理在你模块的 build.gradle.kts 中配置发布签名（一个包含 storeFile、storePassword、keyAlias 和 keyPassword 的 signingConfigs 块，并应用到 release 构建类型）。不要把密码提交到 git（Android 构建文档：https://developer.android.com/build/building-cmdline）。
  2. 在终端中运行 ./gradlew bundleRelease。Gradle 会构建并签名应用包；.aab 通常位于 app/build/outputs/bundle/release/，但请以你自己的构建输出为准。
  3. 如果还没有密钥库，请用 keytool 创建一个并做好备份。上传首个版本时，Google Play 会提供 Play 应用签名。

2. 在 Play 管理中心开启封闭测试

  1. 打开“测试和发布”>“测试”>“封闭测试”，然后点击“创建轨道”（或“管理轨道”）。
  2. 点击“创建新版本”，上传 .aab，填写版本名称和版本说明，点击“保存为草稿”、“下一步”，然后点击“开始发布”（步骤来自 https://support.google.com/googleplay/android-developer/answer/9859348）。
  3. 请先在信息中心完成应用设置任务，否则发布按钮会一直处于禁用状态。

3. 获取 12 名测试员：先免费，后付费

  • 免费方式： 用手机打开 https://testerexchange.com/earn，测试分配给你的应用。你每测试一个应用，就会为你的应用带来一名测试员。
  • 付费方式： 一次性付款，测试员会自动分配。当前价格见 https://testerexchange.com/llms.txt。
  • 申请 15 名测试员而不是 12 名，这样有人中途退出也不会低于 Google 的最低要求。

4. 将 Tester Exchange 连接到 Cursor（可选）

首先在 https://testerexchange.com/api 创建 API 密钥。然后把下面的内容放进项目中的 .cursor/mcp.json，或放进 ~/.cursor/mcp.json 以便在所有项目中使用（文件位置来自 Cursor 的 MCP 文档，https://cursor.com/docs/context/mcp）。请先在 shell 环境中设置 TESTER_EXCHANGE_KEY，避免密钥被提交：

{"mcpServers":{"tester-exchange":{"url":"https://vvrlxzbngxfxddywidoq.supabase.co/functions/v1/mcp","headers":{"Authorization":"Bearer ${env:TESTER_EXCHANGE_KEY}"}}}}

Cursor 会解析 url 和 headers 字段中的 ${env:NAME}。如果服务器加载失败，请打开 Output 面板并选择 MCP Logs。该服务器是基于 Streamable HTTP 的普通 MCP，不使用 OAuth；公共工具（about、pricing、platform_stats）无需密钥即可使用。

5. 向代理提问

  • “用 Tester Exchange 为 com.example.app 获取 15 名测试员，并告诉我在 Play 管理中心需要做什么。”
  • “查看我在 Tester Exchange 上为 com.example.app 创建的活动，告诉我昨天有多少测试员活跃。”
  • “拉取活动报告，并根据真实数据起草我的正式版访问申请回答。”

主要工具是 get_testers：它会添加应用、开启测试，并返回只有人才能完成的步骤，例如在 Play 管理中心添加测试员的 Google 群组。代理无法替你付款，也无法替你点击“申请正式版访问权限”。

没有 MCP？使用 HTTP API

向 https://vvrlxzbngxfxddywidoq.supabase.co/rest/v1/rpc/agent_call 发送 POST 请求，带上 https://testerexchange.com/agents/ 中列出的公开 apikey 请求头，请求体为 {"p_token":"tx_YOUR_TOKEN","p_action":"get_testers","p_args":{"package_name":"com.example.app"}}。接口规范见 https://testerexchange.com/openapi.json。更多工具：https://testerexchange.com/guide/ai-builders/。

常见问题

Cursor 能替我完成 14 天测试吗？

不能。这 14 天需要真实的人在自己的 Android 手机上使用你的应用。Cursor 可以构建应用并完成设置。

Tester Exchange 是 Cursor 的官方集成吗？

不是。它是独立服务，适用于任何支持基于 HTTP 的远程 MCP 的客户端，Cursor 就支持。

AAB 要上传到哪里？

把它上传到 Play 管理中心的封闭测试版本，然后在该轨道上添加测试员的 Google 群组或邮件列表。

有免费获得 12 名测试员的方法吗？

有。在 https://testerexchange.com/earn 测试其他开发者的应用；你每测试一个应用，就会为你的应用带来一名测试员。
